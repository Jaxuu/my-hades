# Feature Specification: 真实 2D 美术与音效资产接入

**Feature Branch**: `024-real-art-assets`

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "将游戏表现层（client/）的占位几何图形替换为真实的 2D 美术与音效资产。玩家角色需替换为带动画的人物模型，敌人替换为对应的怪物贴图，静态墙体替换为 Tilemap 场景纹理。需保留所有底层物理和战斗逻辑，仅在表现层进行资源加载与渲染映射。数据本地化，不依赖后端。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 玩家角色以带动画的人物形象出现 (Priority: P1)

玩家操作的角色不再是一个纯色圆点加一条朝向线，而是一个真正的、会动的 2D 人物形象：站立时有待机动作，移动时切换到移动动作并朝向前进方向，冲刺、攻击、受击与死亡各有对应的视觉表现。玩家仅凭画面就能判断自己面朝哪边、当前处于什么动作。

**Why this priority**: 玩家是屏幕上注视时间最长的对象。它是「这是不是一个游戏」的第一判断标准，也是其余所有美术资产的风格锚点——玩家角色定不下来，敌人与场景就无从对齐。

**Independent Test**: 只实现本故事即可交付：在一个空房间里操作角色，观察待机/移动/冲刺/攻击/受击/死亡是否各有可辨识的画面表现，且朝向始终与移动方向一致。无需敌人或场景美术即可完整验证。

**Acceptance Scenarios**:

1. **Given** 角色静止，**When** 画面更新，**Then** 角色呈现待机动作，且不出现抖动或错位。
2. **Given** 角色向上/下/左/右移动，**When** 位置改变，**Then** 角色形象朝向对应的方向，且切换到移动动作。
3. **Given** 角色执行冲刺或攻击，**When** 动作触发，**Then** 出现与该动作对应的视觉表现，动作结束后回到待机/移动。
4. **Given** 角色受到伤害或被击杀，**When** 该事件发生，**Then** 出现受击表现；死亡时播放死亡表现并消失。

---

### User Story 2 - 敌人以可区分的怪物形象出现 (Priority: P1)

玩家面对的敌人不再是统一的红色方块，而是按种类区分的怪物形象。玩家能在混战中一眼分辨出自己面对的是哪一种敌人（`grunt` 普通、`elite` 精英、`raider` 突袭者、`bomber` 自爆者、`gunner` 远程精英），从而做出正确的应对决策。

**Why this priority**: 敌人的外形直接承载战斗可读性——「哪一种敌人会冲上来、哪一种会远程投掷」必须在抬手的瞬间就能看出来。这是动作游戏的核心可玩性，不是装饰。

**Independent Test**: 只实现本故事即可交付：在一个房间里依次生成每一种敌人，观察每一种是否有专属且可区分的形象，且朝向与死亡表现正常。

**Acceptance Scenarios**:

1. **Given** 数据表中声明的每一种敌人，**When** 该敌人生成，**Then** 它呈现与该种类对应的专属形象。
2. **Given** 同屏存在多种敌人，**When** 玩家观察画面，**Then** 仅凭形象（不依赖颜色差异）即可区分敌人类别。
3. **Given** 敌人朝向玩家移动或攻击，**When** 其朝向改变，**Then** 敌人形象朝向同步改变。
4. **Given** 敌人被击杀，**When** 死亡发生，**Then** 播放与既有死亡表现一致的消亡效果。

---

### User Story 3 - 房间墙体与地面呈现为连贯的场景纹理 (Priority: P2)

房间不再由扁平的色块拼成，而是呈现为一张连贯的场景：墙体是有纹理的墙面/障碍物，地面是有材质感的地板。房间的形状与可通行区域仍然一目了然，且与玩家实际能碰撞到的范围完全一致。

**Why this priority**: 场景是「这个地方像不像一个地方」的来源，也是玩家判断哪里能走、哪里是墙的唯一直观依据。优先级低于角色与敌人，因为它不改变战斗决策，但显著影响沉浸感与空间可读性。

**Independent Test**: 只实现本故事即可交付：加载任意一间房间，观察墙体与地面是否呈现为连贯纹理，且视觉上的墙与角色实际被阻挡的位置完全重合。

**Acceptance Scenarios**:

1. **Given** 任一房间被加载，**When** 画面渲染，**Then** 墙体呈现为纹理化的场景元素而非单色方块，地面呈现为连续的材质底面。
2. **Given** 角色沿墙移动，**When** 角色贴住视觉上的墙面，**Then** 角色恰好在此处被阻挡，视觉边界与碰撞边界无可见偏差。
3. **Given** 房间尺寸或形状不同（如小型起始房、带柱子的竞技场、30×30 压测房），**When** 加载该房间，**Then** 纹理按房间实际尺寸铺展，不拉伸、不重复错位。

---

### User Story 4 - 打击、冲刺与拾取使用真实音效 (Priority: P2)

命中、冲刺与拾取金币不再播放代码合成的占位音，而是播放真实的音效资产。每一次输入与反馈都有清晰的听觉回报，与画面上的顿帧、击退、火花同步。

**Why this priority**: 音效与既有打击感是同一套体验的一部分，用户明确要求替换为真实资产。它不改变玩法，但直接决定「打起来爽不爽」。

**Independent Test**: 只实现本故事即可交付：在浏览器中触发命中、冲刺与拾取，确认每一类都播放了与占位音不同的真实音效，且与画面反馈对齐。

**Acceptance Scenarios**:

1. **Given** 一次攻击命中目标，**When** 命中发生，**Then** 播放命中的真实音效。
2. **Given** 角色执行冲刺，**When** 冲刺触发，**Then** 播放冲刺的真实音效。
3. **Given** 玩家拾取金币，**When** 金币增加，**Then** 播放拾取的真实音效。
4. **Given** 音频被浏览器策略阻止或环境无音频能力，**When** 上述事件发生，**Then** 游戏静默继续，不报错、不卡顿。

---

### User Story 5 - 资产全部本地化，缺失时优雅降级 (Priority: P3)

游戏的全部美术与音效资产随应用一起分发，打开游戏即可看到与听到，不需要任何后端或网络服务。若个别资产缺失或损坏，游戏仍能正常游玩，只是该处回退到占位表现，绝不出现黑屏或崩溃。

**Why this priority**: 它是一条交付保障而非新体验。放在最后是因为它约束的是「怎么交付」，而不是「交付什么」；但它必须在任何一次上线前成立。

**Independent Test**: 只实现本故事即可交付：在完全离线的环境下打开游戏，确认所有画面与音效正常；再人为移除/损坏单个资产文件，确认游戏仍可游玩。

**Acceptance Scenarios**:

1. **Given** 完全离线的环境，**When** 游戏启动并游玩，**Then** 全部画面与音效正常呈现，不发起任何对外部服务的请求。
2. **Given** 某一个美术或音效资产缺失或损坏，**When** 游戏运行到需要它的时刻，**Then** 该处回退到占位表现（或静默），其余部分不受影响，游戏不崩溃。
3. **Given** 启动时资产尚未就绪，**When** 游戏开始，**Then** 玩家不会看到残缺或闪烁的画面。

---

### User Story 6 - 全部屏上元素与界面统一到同一美术风格 (Priority: P3)

屏幕上的每一个元素——掉落物、危险预警、命中火花、冲刺拖尾、伤害数字，以及 HUD、奖励三选一菜单、死亡/胜利/营地覆盖层——都换成与角色和场景同一套美术语言的资产，不再残留任何占位几何或浏览器默认控件外观。玩家从进入游戏到结束一局，视觉风格始终连贯。

**Why this priority**: 它决定「完成度」而非「可玩性」。放在 P3 是因为前五个故事已构成完整可玩的体验；但没有它，画面会在一半处突然「退回原型」，产品级观感不成立。

**Independent Test**: 只实现本故事即可交付：完整走一遍「开局 → 战斗 → 拾取/受伤 → 清房 → 三选一 → 通关/死亡 → 营地 → 再次开局」，确认全程没有任何一处仍是占位几何或浏览器默认控件样式。

**Acceptance Scenarios**:

1. **Given** 玩家拾取掉落物，**When** 掉落物出现，**Then** 它呈现为符合该风格的资产，且「应拾取」与「应躲避」两类在视觉上绝不混淆。
2. **Given** 危险预警出现，**When** 预警生效，**Then** 它以符合风格的预警资产呈现，且能清晰传达危险范围与时机。
3. **Given** HUD 显示生命、金币与房间进度，**When** 数值变化，**Then** HUD 采用统一风格的视觉呈现，文字清晰可读。
4. **Given** 清空房间触发奖励三选一，**When** 菜单出现，**Then** 三个选项以统一风格的卡片/图标呈现，且可点击选择。
5. **Given** 一局结束或回到营地，**When** 对应覆盖层出现，**Then** 死亡/胜利/营地界面均采用统一风格，而非浏览器默认控件。

---

### Edge Cases

- 当某个精灵/贴图/音频文件缺失、损坏或格式不被支持时，游戏如何表现？（必须降级而非崩溃）
- 当浏览器自动播放策略阻止音频、或环境完全没有音频能力时，如何表现？（必须静默继续）
- 当数据表中出现了美术资产未覆盖的敌人类别时，如何表现？（必须回退到默认形象而非不可见）
- 当同屏实体数量极高（如 150 敌人的压测房间）时，动画与贴图渲染是否仍然流畅？
- 当角色朝向正好处在方向切换的临界角度时，形象朝向是否会抖动或来回闪烁？
- 当角色在移动中突然死亡、或在冲刺中受击时，动画状态如何收束？
- 当房间形状不规则（非矩形、带内部柱子）时，纹理铺设是否出现错位或空洞？
- 当窗口尺寸变化、相机移动时，场景纹理是否出现撕裂或错位？
- 当玩家开启系统的「减少动态效果」偏好时，是否有合理的降级？（可选）
- 当界面文字为中文、而字体资产缺失或未覆盖中文字形时，文字是否仍然可读？（不得出现乱码/方块）
- 当三选一菜单的图标资产缺失时，选项是否仍然可点击、可辨识，且不影响选择与推进？
- 当同一套美术资产需要同时服务「局内（世界空间）」与「界面（屏幕空间）」两种尺度时，放大/缩小是否出现明显失真？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 玩家角色 MUST 以带动画的人物形象呈现，取代当前的纯几何占位（圆点 + 朝向线）。
- **FR-002**: 玩家形象 MUST 支持至少「待机」与「移动」两种动作，并在两者之间自然切换。
- **FR-003**: 玩家形象 MUST 朝向与模拟层公布的朝向一致，且朝向切换 MUST 平滑（无长弧旋转、无抖动）。
- **FR-004**: 玩家形象 MUST 对模拟层已公布的其它动作状态（冲刺、攻击、受击、死亡）给出可辨识的视觉表现。
- **FR-005**: 每一种在数据表中声明的敌人类别 MUST 映射到专属且可区分的形象；区分 MUST 在形态层面成立，不依赖颜色差异。
- **FR-006**: 敌人形象 MUST 朝向与模拟层公布的朝向一致，并 MUST 具有与既有表现一致的死亡效果。
- **FR-007**: 房间静态几何 MUST 以「由本地纹理资产铺成的场景」呈现，取代当前的单色方块；地面与墙体 MUST 呈现为连贯的材质。
- **FR-008**: 场景纹理的可见边界 MUST 与模拟层的碰撞几何一致：视觉上是墙的地方就是被阻挡的地方，误差在玩家可察觉范围内为零。
- **FR-009**: 场景纹理 MUST 依据房间实际尺寸与形状铺设，MUST NOT 出现拉伸、错位或空洞。
- **FR-010**: 命中、冲刺与拾取三类音频事件 MUST 使用真实音效资产，取代代码合成的占位音。
- **FR-011**: 音效 MUST 与对应的画面反馈保持同步：音效触发 MUST 落在对应画面反馈的**同一渲染帧**（至迟下一帧），MUST NOT 出现跨帧可察觉的错位。
- **FR-012**: 全部美术与音效资产 MUST 随应用本地分发；游戏 MUST NOT 依赖任何后端或网络服务来呈现或播放它们。
- **FR-013**: 资产失效 MUST 分两层处理：**构建期** —— 清单引用的资产文件**缺失**时，构建 MUST 响亮失败（MUST NOT 静默产出缺资产的产物）；**运行期** —— 资产**损坏、解码失败或格式不受支持**时，系统 MUST 优雅降级（回退到占位表现或静默），MUST NOT 崩溃、黑屏或阻塞游戏循环。
- **FR-014**: 模拟层行为 MUST 保持不变：在相同种子与相同输入下，模拟产生的状态序列 MUST 与改动前逐 Tick 一致；MUST NOT 改动任何玩法数值或规则。
- **FR-015**: 表现层的改动 MUST NOT 引入任何从模拟核心指向表现层的依赖；依赖方向 MUST 保持单向。
- **FR-016**: 在既有压测场景（约 150 个敌人同屏，`?mode=stress`）下，表现层的渲染开销 MUST NOT 相对基线出现实质增长；验收口径 MUST 为**同机、同场景、同一脚本**下的耗时**比值**（改动后 / 改动前 ≤ 1.2），MUST NOT 使用绝对墙钟阈值（宪法 Principle IV）。
- **FR-017**: 全部局内屏上元素——掉落物、危险预警、命中火花、冲刺拖尾、伤害数字——MUST 采用与新资产集一致的视觉资产，取代占位几何；其中「应拾取」与「应躲避」两类 MUST 在视觉上清晰可辨、MUST NOT 混淆。
- **FR-018**: HUD、奖励三选一菜单，以及死亡/胜利/营地覆盖层 MUST 采用同一套美术风格的资产呈现，MUST NOT 残留浏览器默认控件外观。
- **FR-019**: 界面文字 MUST 在目标平台保持清晰可读（含中文），MUST NOT 因字体缺失或未覆盖字形而出现乱码或方块。
- **FR-020**: 全部美术与音效资产 MUST 来自**开放许可**来源（CC0 / 公共领域 / 明确允许再分发的授权）或**本仓库原创 / 程序化生成**。MUST NOT 再分发任何商业游戏的专有资产（含《哈迪斯》原版精灵图、贴图与音频），亦 MUST NOT 使用无明确再分发授权的同人素材。每项资产 MUST 登记其来源与许可。
- **FR-021**: 资产的美术风格 MUST 统一朝向「希腊神话题材 · 俯视动作肉鸽」的视觉语言（与《哈迪斯》的观感方向一致），且 MUST 为可合法分发的独立资产。
- **FR-022**: 本特性的视觉覆盖范围 MUST 为**全量**：玩家角色 + 全部敌人 + 墙体/场景 + 全部局内特效与掉落物 + 全部界面（HUD / 奖励三选一 / 死亡 / 胜利 / 营地）。MUST NOT 遗留任何一处占位几何或默认控件。

### Key Entities *(include if feature involves data)*

- **玩家角色形象**：玩家实体的可视代表；关键属性为「动作状态」「朝向」，需覆盖待机/移动/冲刺/攻击/受击/死亡。
- **敌人类别形象**：由数据表声明的每一种敌人到专属形象的映射。canonical id ↔ 中文标签：`grunt`（普通）· `elite`（精英）· `raider`（突袭者）· `bomber`（自爆者）· `gunner`（远程精英）。关键属性为「类别」「朝向」「死亡表现」。
- **场景纹理集**：构成房间外观的墙体与地面纹理；与房间的网格地形（墙格/空地/出生点）一一对应。
- **音效资产集**：命中、冲刺、拾取三类事件的音频资产；关键属性为「事件类型」「与画面的同步时机」。
- **局内特效与掉落物资产**：命中火花、冲刺拖尾、危险预警、伤害数字，以及掉落物（金币 / 治疗 / 暗影）的视觉资产；关键属性为「元素类型」「应拾取 / 应躲避」的视觉区分。
- **界面资产集**：HUD、奖励三选一菜单、死亡 / 胜利 / 营地覆盖层的视觉资产与字体；关键属性为「界面状态」「文字可读性」。
- **资产许可登记**：逐项记录每份资产的来源与许可（用于合规审查），确保 100% 可追溯且不含商业游戏专有资产。
- **资产清单（本地）**：本特性引入的全部美术与音效资产的登记表，用于启动加载与缺失检测；不含任何远端引用。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在角色静止、四个方向移动、冲刺、攻击、受击、死亡共 8 种情形下，观察者能在 1 秒内正确说出角色当前朝向与所处动作，成功率 100%。
- **SC-002**: 在 5 种敌人类别两两混合的同屏场景中，观察者仅凭形象（关闭颜色线索）识别类别的正确率 ≥ 90%。
- **SC-003**: 可见墙体的边界与实际碰撞边界的一致率为 100%（在任意房间中，视觉上「能走进去」的位置都必须真的能走进去）。
- **SC-004**: 在固定的种子与固定输入序列下，改动前后的模拟结果逐 Tick 完全一致（0 处差异），证明玩法行为未被改变。
- **SC-005**: 在完全离线的环境下，游戏的全部画面与音效可用，且对外部服务的请求数为 0。
- **SC-006**: 在约 150 个敌人同屏的压测场景（`?mode=stress`）下，表现层**每帧耗时中位数**的「改动后 / 改动前」**比值 ≤ 1.2**（同机、同场景、连续 3 次取中位数）。判定 MUST 使用比值，MUST NOT 使用绝对墙钟阈值（宪法 Principle IV）。
- **SC-007**: 人为移除/损坏任意单个资产后，游戏仍能进入可玩状态，崩溃次数为 0、黑屏次数为 0。
- **SC-008**: 命中、冲刺、拾取三类事件，其音效触发与对应画面反馈落在**同一渲染帧**（允许至迟 1 帧）；观察者判定为「同步」的比例 = 100%。
- **SC-009**: 完整走完「开局 → 战斗 → 清房 → 三选一 → 终局 → 营地 → 再开局」全流程，观察者找不到任何一处仍是占位几何或浏览器默认控件（残留处数 = 0）。
- **SC-010**: 全部资产的许可可被逐项追溯（有明确来源与许可的比例 = 100%），且经审查不含任何商业游戏专有资产。
- **SC-011**: 全部美术与音效资产的总量 ≤ **6 MB**，且单文件 ≤ **1 MB**（构建产物实测）。

## Assumptions

- 目标平台仍为桌面浏览器，操作方式（键盘移动/攻击/冲刺）保持不变；本特性不引入新的玩法机制。
- 模拟核心（确定性逻辑层）被视为**冻结资产**：本特性只在表现层做「状态/事件 → 美术与音效」的映射，不修改任何玩法规则或数值。
- 占位图形不会被删除，而是保留为资产缺失时的**回退表现**。
- 资产以文件形式随应用本地分发并提交到仓库；不引入外部 CDN 或后端服务。
- 音效继续保持「尽力而为」语义：无音频能力或自动播放被阻止时静默降级，绝不阻塞游戏。
- 动画的帧数与方向数按既有模拟层公布的状态与朝向设计（不新增模拟层状态），具体帧率/方向数以规格后续澄清与规划为准。
- 现有「打击感」机制（顿帧、击退、屏幕震动、火花）保持不变，本特性只替换其视觉与听觉素材来源。
- **覆盖范围为全量（FR-022）**：玩家角色、全部敌人、墙体/场景、全部局内特效与掉落物，以及 HUD / 奖励三选一 / 死亡 / 胜利 / 营地全部界面，均在本次范围内。
- **素材来源受许可约束（FR-020）**：资产取自开放许可素材库（CC0 / 公共领域 / 明确允许再分发）或本仓库原创 / 程序化生成。原计划「直接抓取《哈迪斯》原版或同人素材」因**版权与公开仓库再分发风险**被替换为「同一美术风格（希腊神话 · 俯视动作肉鸽）的合法资产」，观感目标不变、素材来源变更。若用户能提供相应授权证明，可另行推翻该约束。
- 资产将随仓库提交（含许可登记），仓库体积会增大。**体积预算**：美术与音效资产总量 MUST ≤ **6 MB**、单文件 MUST ≤ **1 MB**（对应 SC-011）；按 D7 不打包全量 CJK 字体。
- **已知限制（敌人形象分类）**：敌人形象的「能力签名」分类器（见 `contracts/renderer-asset-mapping.md` §4 / §6）以**基础类型**为准。非 `grunt` 的**精英变体**（如 `spawnElite('gunner')`，签名为 armor + hazard）按**基础类型**（`gunner`）呈现，不额外区分「精英化」。这满足 FR-005 对「数据表中声明的敌人类别」的要求，但不承诺区分同一类别的精英变体。
