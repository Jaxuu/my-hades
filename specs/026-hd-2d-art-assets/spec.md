# Feature Specification: 高清 2D 美术与动画资产替换（M18）

**Feature Branch**: `026-hd-2d-art-assets`

**Created**: 2026-10-02

**Status**: Draft

**Input**: User description: "彻底废弃并移除现有的低分辨率像素资产及生成工具（如 build-atlas.py）。在表现层（client/）全面接入高清（HD）2D 美术与动画资源。要求：1. 玩家与敌人替换为高分辨率的 2D 序列帧或 Spine 骨骼动画，具备流畅的待机、移动、攻击与受击表现；2. 关卡环境替换为高清地牢 Tilemap（包含带深度与透视关系的墙体和精细地面贴图）；3. 此次升级为纯渲染层视效替换，绝对禁止修改逻辑层（src/）的碰撞体积、判定逻辑或帧同步核心；4. 现有的 893 个测试用例必须 100% 保持绿灯。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 玩家角色呈现为高清动画形象 (Priority: P1)

玩家操作的角色不再是一张 16×16 的像素小人放大后糊成色块，而是一个高分辨率的、动作流畅的人物形象：站立时有呼吸感的待机循环，移动时有奔跑/行走循环并朝向前进方向，攻击时有清晰的挥击起手与收招，受击时有可辨识的受创反馈。玩家仅凭画面就能判断「我面朝哪边、我现在在做什么、我有没有被打到」。

**Why this priority**: 玩家是屏幕上注视时间最长、动作最频繁的对象，也是「这是不是一个高清游戏」的第一判断标准。它是其余所有高清资产的风格锚点——玩家的清晰度与动作节奏定不下来，敌人与场景就无从对齐。缺少本故事，整个特性没有可交付价值。

**Independent Test**: 只实现本故事即可交付：在一个空房间里操作角色，观察待机、移动（四向）、攻击、受击四种表现是否都清晰流畅、朝向与移动方向一致，且画面在放大显示下不出现马赛克或锯齿。无需敌人或地牢美术即可完整验证。

**Acceptance Scenarios**:

1. **Given** 角色静止，**When** 画面更新，**Then** 角色播放待机动作循环，动作连续、无跳帧、无错位。
2. **Given** 角色向上/下/左/右移动，**When** 位置改变，**Then** 角色切换到移动动作并朝向对应方向，且动作与位移方向一致。
3. **Given** 角色发起攻击，**When** 攻击动作触发，**Then** 出现清晰的攻击表现，动作结束后回到待机或移动。
4. **Given** 角色受到伤害，**When** 受击事件发生，**Then** 出现可辨识的受创表现，且不影响后续动作衔接。
5. **Given** 角色在 100%–400% 显示倍率下被观察，**When** 观察者近距离查看，**Then** 角色形象保持清晰，不出现像素块放大或明显锯齿。

---

### User Story 2 - 敌人呈现为高清且可区分的怪物形象 (Priority: P1)

玩家面对的敌人不再是放大的像素方块，而是高分辨率、按种类区分的怪物形象。每种敌人都有待机、移动、攻击与受击表现，玩家能在混战中一眼分辨出自己面对的是哪一种敌人（`grunt` 普通、`elite` 精英、`raider` 突袭者、`bomber` 自爆者、`gunner` 远程精英），并在其抬手瞬间读出「它要冲上来还是远程投掷」。

**Why this priority**: 与玩家同级的核心可玩性——敌人的外形与动作承载战斗可读性，是玩家做出闪避/进攻决策的唯一依据。若敌人仍是模糊色块，战斗将退化为盲猜。

**Independent Test**: 只实现本故事即可交付：在一个房间里依次生成每一种敌人，观察每一种是否有专属且可区分的形象，是否具备待机/移动/攻击/受击表现，且朝向与死亡表现正常。

**Acceptance Scenarios**:

1. **Given** 数据表中声明的每一种敌人类别，**When** 该敌人生成，**Then** 它呈现与该种类对应的专属高清形象。
2. **Given** 同屏存在多种敌人，**When** 玩家观察画面，**Then** 仅凭形象（关闭颜色线索）即可区分敌人类别。
3. **Given** 敌人朝向玩家移动或发起攻击，**When** 其动作/朝向改变，**Then** 敌人形象的动作与朝向同步改变，攻击有可辨识的起手表现。
4. **Given** 敌人受到伤害或被击杀，**When** 事件发生，**Then** 出现受击表现；死亡时播放与既有表现一致的消亡效果。

---

### User Story 3 - 关卡环境呈现为带深度感的高清地牢 (Priority: P1)

房间不再是扁平的色块拼接，而是一个有纵深的地牢空间：墙体是具有立面与顶面的立体墙体，能读出「这堵墙有多高、它在房间的哪一侧」；地面是精细的材质贴图（石板/砖纹），能读出空间的走向。玩家对「哪里是墙、哪里能走、房间有多大」的判断依然一目了然，且与角色实际被阻挡的位置完全一致。

**Why this priority**: 与角色/敌人同为 P1——它是「这个地方像不像一个地牢」的来源，也是玩家判断可通行区域的唯一直观依据。带深度与透视的墙体正是用户对「高清地牢 Tilemap」的明确要求（区别于当前的扁平色块）。

**Independent Test**: 只实现本故事即可交付：加载任意一间房间，观察墙体是否呈现立体深度、地面是否呈现连续精细材质，且视觉上的墙与角色实际被阻挡的位置完全重合；遍历小型起始房、带柱子的竞技场与 30×30 压测房，确认铺设无拉伸错位。

**Acceptance Scenarios**:

1. **Given** 任一房间被加载，**When** 画面渲染，**Then** 墙体呈现为带立面/顶面的立体墙体，地面呈现为连续的高清材质底面，均不再出现单色方块。
2. **Given** 角色沿墙移动，**When** 角色贴住视觉上的墙面，**Then** 角色恰好在此处被阻挡，视觉边界与碰撞边界无可见偏差。
3. **Given** 房间尺寸或形状不同（小型起始房、带柱子的竞技场、30×30 压测房），**When** 加载该房间，**Then** 纹理按房间实际尺寸铺展，不拉伸、不重复错位、不出现空洞。
4. **Given** 存在带深度的墙体，**When** 角色在墙脚行走或墙后存在地面，**Then** 墙体的立体表现不遮挡本应可见的可通行地面，可通行区域仍然清晰可辨。

### User Story 4 - 纯表现层替换，玩法与逻辑逐 Tick 不变 (Priority: P1)

无论画面变得多么高清，游戏的玩法完全不变：角色的碰撞体积、移动速度、攻击距离、伤害判定、帧同步核心都与改动前逐 Tick 一致。这次升级只改变「看起来是什么样」，绝不改变「实际是什么」。

**Why this priority**: 这是用户明确写下的硬约束（要求 3），也是项目的安全底线。一旦被违反，整个确定性保证与 893 例回归基线即刻作废。它必须与 P1 资产故事同时成立，而不是事后补票。

**Independent Test**: 只实现本故事即可交付：在固定种子与固定输入序列下，分别以「改动前」与「改动后」运行同一段模拟，比较两次产生的状态序列与快照摘要；并检查改动后的源码差异中逻辑内核的文件数为零。

**Acceptance Scenarios**:

1. **Given** 相同的种子与相同的输入序列，**When** 分别在改动前与改动后运行模拟，**Then** 两次产生的状态逐 Tick 完全一致（差异处数 = 0），且快照摘要逐位相同。
2. **Given** 高清资产全部就位，**When** 检查依赖方向，**Then** 不存在任何从逻辑内核指向表现层的依赖；逻辑内核的改动文件数为 0。
3. **Given** 高清资产全部就位，**When** 玩家贴墙移动、攻击命中或与敌人碰撞，**Then** 被阻挡的位置、判定范围与命中时机与改动前一致。
4. **Given** 高清资产全部就位，**When** 检查逐 Tick 管道，**Then** 管道段数与顺序不变。

---

### User Story 5 - 低分辨率像素资产与生成工具被彻底移除 (Priority: P2)

仓库里不再残留任何低分辨率像素美术资产，也不再保留「用程序化变换从像素素材派生出精灵图」的生成工具与像素源素材包。新接入的全部是高清资产，且每项资产都有可追溯的开放许可登记。构建产物中不存在旧像素资产，也不存在对它们的任何引用。

**Why this priority**: 这是用户的第一条要求（「彻底废弃并移除」）。它不是新增体验，而是交付洁净度的保障：留着旧资产与生成器，就等于留着「随时退回像素风」的歧义与仓库冗余。优先级低于前三者，因为它必须在高清资产已就位之后才有意义。

**Independent Test**: 只实现本故事即可交付：在仓库中检索低分辨率像素资产与生成工具，确认残留数为零；确认构建产物中不包含旧像素资产，且构建仍然成功。

**Acceptance Scenarios**:

1. **Given** 高清资产已接入，**When** 检索仓库，**Then** 低分辨率像素精灵图资产与像素派生生成工具的残留数为 0。
2. **Given** 旧资产已被移除，**When** 执行构建，**Then** 构建成功，且产物中不包含旧像素资产文件。
3. **Given** 全部高清资产，**When** 查阅许可登记，**Then** 每一项资产都能追溯到明确的开放许可或本仓库原创来源。

---

### User Story 6 - 高清资产在放大显示与视口变化下保持锐利 (Priority: P2)

在高分辨率屏幕上（相机已按 M17 的缩放机制放大世界），高清资产仍然清晰锐利：放大时不出现像素块、不糊、不出现明显锯齿或摩尔纹；窗口尺寸变化、相机移动时，画面不出现纹理撕裂或错位。

**Why this priority**: 高清化的收益只有在「放大后仍然清晰」时才兑现。它与 M17 的相机缩放直接耦合——若资产分辨率不足或采样方式不当，放大后高清资产会重新退化成「糊掉的像素」，本特性即失去意义。优先级低于前四条，因为它依赖前四条已成立。

**Independent Test**: 只实现本故事即可交付：在多种视口尺寸与多个相机缩放倍率下，观察玩家、敌人与地牢纹理，确认在放大倍率下仍保持清晰、无撕裂。

**Acceptance Scenarios**:

1. **Given** 相机处于较高缩放倍率，**When** 观察角色与地牢纹理，**Then** 画面保持清晰，不出现像素块放大或明显锯齿。
2. **Given** 视口尺寸变化，**When** 画面重新适配完成，**Then** 高清纹理不出现撕裂、错位或空洞。
3. **Given** 相机在房间内移动或玩家移动，**When** 场景滚动，**Then** 地牢纹理稳定贴合，不出现抖动或漂移。

---

### User Story 8 - 局内特效与掉落物呈现为高清资产 (Priority: P2)

战斗中的即时反馈不再残留像素时代的粗糙几何：命中时的火花、冲刺时的拖尾、危险预警环、伤害数字，以及清房后掉落的金币/治疗/暗影，都换成与角色和地牢同一套美术语言的 HD 资产。玩家能一眼分清「这个东西应该去捡」和「这个圈必须躲开」。

**Why this priority**: 它是 FR-030「局内世界美术」的第四个组成部分（玩家、敌人、地牢环境之外的最后一个）。它不是可玩性的前提，但决定「画面是否在一半处突然退回原型」——若只有角色与地牢高清化，战斗反馈仍是旧几何，整体观感不成立。定为 P2 是因为前三条 P1 故事已构成完整可玩的核心体验。

**Independent Test**: 只实现本故事即可交付：触发一次命中、一次冲刺、一次危险预警、一次拾取与一次击杀，观察每一类是否呈现为 HD 资产、彼此风格统一，且「应拾取」与「应躲避」两类在视觉上不混淆。无需玩家/敌人/地牢美术即可完整验证。

**Acceptance Scenarios**:

1. **Given** 一次攻击命中目标，**When** 命中发生，**Then** 呈现 HD 火花表现（而非纯几何线条），且与既有打击感（顿帧、击退、震屏）同步。
2. **Given** 角色执行冲刺，**When** 冲刺触发，**Then** 呈现 HD 拖尾表现。
3. **Given** 危险预警出现，**When** 预警生效，**Then** 以 HD 预警环呈现，且其进度仍由既有引信驱动、与判定时机一致。
4. **Given** 掉落物出现（金币 / 治疗 / 暗影），**When** 玩家观察，**Then** 三类各具可区分的 HD 形象，且「应拾取」与「应躲避」两类在视觉上绝不混淆。
5. **Given** 造成伤害，**When** 伤害数字浮出，**Then** 数字使用 HD 字形呈现、清晰可读。

---

### User Story 7 - 既有回归基线零回归 (Priority: P3)

本特性落地后，项目既有的逻辑与玩法测试全部保持通过，既有的渲染场景图冻结契约一条都不被破坏。凡因「资产结构本身被替换」而必须调整的资产结构断言，都在本规格中显式登记，绝不做隐性的放宽或删除。

**Why this priority**: 它是一条交付保障而非新体验。放在最后是因为它约束的是「怎么交付」而不是「交付什么」；但它必须在任何一次合并前成立。

**Independent Test**: 只实现本故事即可交付：运行完整测试套件，确认逻辑与玩法测试 100% 通过；确认渲染场景图冻结契约断言在未修改的前提下继续成立。

**Acceptance Scenarios**:

1. **Given** 改动完成，**When** 运行完整测试套件，**Then** 逻辑内核与玩法的测试用例 100% 通过（失败 0）。
2. **Given** 改动完成，**When** 检查渲染场景图的冻结契约，**Then** 全部契约在未修改其断言的前提下继续成立。
3. **Given** 任何资产结构断言被调整，**When** 审查变更，**Then** 该调整已在本规格中显式登记，且不存在未登记的放宽或删除。

---

### Edge Cases

- 当某个高清资产文件缺失、损坏、格式不被支持或解码失败时，如何表现？（必须优雅降级到占位表现或静默，而非崩溃或黑屏）
- 当高清资产的体积超出既有体积预算（总量 ≤ 6 MB / 单文件 ≤ 1 MB）时，如何表现？（构建必须给出明确判定，而非静默超限）
- 当高清图集声明的帧矩形越界、帧数不足或某个动作/朝向缺帧时，如何表现？（必须降级到占位表现或安全帧，而非渲染出残缺、空白或撕裂的精灵）
- 当同屏实体数量极高（约 150 敌人的压测房间）时，高清资产的加载内存与逐帧开销是否仍然可接受？
- 当相机缩放处于上下限两端时，高清纹理是否出现模糊、锯齿或摩尔纹？
- 当房间形状不规则（非矩形、带内部柱子）时，带深度的墙体与地面纹理铺设是否出现错位、遮挡错误或空洞？
- 当角色朝向正好处在方向切换的临界角度时，形象朝向是否会抖动或来回闪烁？
- 当角色在移动中突然死亡、或在攻击/冲刺中受击时，动画状态如何收束？
- 当某个敌人类别在数据表中出现、但高清资产未覆盖该类别时，如何表现？（必须回退到默认形象而非不可见）
- 当显示倍率取非整数（如 1.5×、2.5×）时，高清纹理是否出现采样抖动或接缝？
- 当系统开启「减少动态效果」偏好时，是否有合理的降级？（可选）
- 当旧像素资产被移除、而某处仍残留对它的引用时，构建是否响亮失败？（必须失败，而非产出 404 的产物）

## Requirements *(mandatory)*

### Functional Requirements

#### 高清角色与敌人动画

- **FR-001**: 玩家角色形象 MUST 替换为高分辨率动画资产，取代当前的像素精灵图；表现 MUST 覆盖待机、移动、攻击、受击四种基本动作，并 MUST 保留既有的冲刺与死亡表现。
- **FR-002**: 玩家形象 MUST 支持至少四个朝向（上/下/左/右），且朝向 MUST 与模拟层公布的方向一致。
- **FR-003**: 玩家动作的切换 MUST 完全由模拟层已公布的状态驱动；MUST NOT 为动画新增任何模拟层状态或字段。
- **FR-004**: 每一种在数据表中声明的敌人类别 MUST 映射到专属且可区分的高清形象；区分 MUST 在形态层面成立，不依赖颜色差异。
- **FR-005**: 敌人形象 MUST 具备待机、移动、攻击、受击四种表现，朝向 MUST 与模拟层公布的方向一致，并 MUST 保留与既有表现一致的死亡效果。
- **FR-006**: 高清角色与敌人动画 MUST 在视觉上连续流畅，且判定 MUST 可量化（消除「长时间」「流畅」这类不可测表述）：① 待机与移动 MUST 为循环动作；② 攻击与受击 MUST 有明确起止（停在末帧、不回绕）；③ 任一动作的**相邻帧显示间隔 MUST ≤ 该动作标称帧时长的 1.5 倍**（无跳帧）；④ 动作切换前后 MUST 均显示非空帧（无空白帧 / 闪烁）；⑤ 除 `death` 外的动作，其单次连续显示时长 MUST ≤ 该动作标称总时长的 2 倍（无僵直）。

#### 高清地牢环境

- **FR-007**: 房间静态几何 MUST 以高清地牢 Tilemap 呈现，取代当前的扁平色块；墙体 MUST 具有深度与透视关系（可读出立面与顶面），地面 MUST 呈现为精细材质贴图。
- **FR-008**: 场景的可见边界 MUST 与模拟层的碰撞几何一致：视觉上是墙的地方就是被阻挡的地方，偏差在玩家可察觉范围内为零。
- **FR-009**: 场景纹理 MUST 依据房间实际尺寸与形状铺设，MUST NOT 出现拉伸、错位、重复错位或空洞。
- **FR-010**: 带深度的墙体表现 MUST NOT 遮挡本应可见的可通行地面；可通行区域 MUST 始终保持清晰可辨。

#### 纯表现层替换（硬约束）

- **FR-011**: 本特性的全部改动 MUST 只发生在表现层（`client/` 及其资产）；逻辑内核（`src/`）的改动文件数 MUST 为 0。
- **FR-012**: 玩法行为 MUST 保持不变：在相同种子与相同输入下，模拟产生的状态序列与快照摘要 MUST 与改动前逐 Tick 一致。
- **FR-013**: 依赖方向 MUST 保持单向（表现层 → 逻辑内核）；MUST NOT 引入任何从逻辑内核指向表现层的依赖。
- **FR-014**: 逐 Tick 管道 MUST 保持既有段数与顺序不变；MUST NOT 为渲染需要而增删或重排任何段。
- **FR-015**: 表现层 MUST 仍是模拟世界的只读消费者：MUST NOT 调用任何写 API，MUST NOT 推进模拟。

#### 旧像素资产的移除

- **FR-016**: 现有的低分辨率像素美术资产（像素精灵图集及其图集描述）MUST 被移除，仓库 MUST NOT 再引用它们。
- **FR-017**: 用于从像素素材派生精灵图的生成工具（如 `build-atlas.py`）MUST 被移除。
- **FR-018**: 用于派生像素资产的像素源素材包 MUST 被移除或退役；仓库 MUST NOT 再包含仅服务于旧像素管线的源素材。
- **FR-019**: 资产引用点 MUST 保持单一：全仓库 MUST 只有一处模块引用资产文件，且该引用 MUST 在构建期解析，使得引用缺失资产时构建响亮失败。
- **FR-020**: 构建产物中 MUST NOT 残留旧像素资产文件，且构建 MUST 成功。

#### 资产分发、许可与体积

- **FR-021**: 全部高清资产 MUST 随应用本地分发；游戏 MUST NOT 依赖任何后端或网络服务来呈现它们（外部请求数 = 0）。
- **FR-022**: 运行期资产损坏、解码失败或格式不受支持时，系统 MUST 优雅降级（回退到占位表现），MUST NOT 崩溃、黑屏或阻塞游戏循环。
- **FR-023**: 全部高清资产 MUST 来自开放许可来源（CC0 / 公共领域 / 明确允许再分发）或本仓库原创 / 程序化生成；MUST NOT 再分发任何商业游戏的专有资产，亦 MUST NOT 使用无明确再分发授权的同人素材。每项资产 MUST 逐项登记其来源与许可。
- **FR-024**: 高清资产的体积 MUST 满足本特性更新后的体积预算（总量与单文件上限），并以构建产物实测为准；预算的具体数值 MUST 在规划阶段确定并记录。

#### 与既有系统的协同

- **FR-025**: 高清资产在相机缩放生效时 MUST 保持清晰锐利；放大显示下 MUST NOT 出现像素块放大、明显锯齿或摩尔纹。
- **FR-026**: 在既有压测场景（约 150 个敌人同屏）下，表现层渲染开销 MUST NOT 相对基线出现实质增长；验收口径 MUST 为**同机、同场景、同一脚本**下的耗时**比值**（改动后 / 改动前 ≤ 1.2），MUST NOT 使用绝对墙钟阈值。
- **FR-027**: 既有渲染场景图的冻结契约 MUST NOT 被破坏；若新增常驻节点，MUST 采用惰性挂载或为契约补充显式同步钉桩，MUST NOT 放宽或删除既有断言。
- **FR-028**: 既有**渲染**测试套件中**不属于** `tests/render/*_art` 的部分（相机缩放 `camera_zoom_*.test.ts`、插值 `interpolation.test.ts`、桥接 `renderer_bridge.test.ts`、打击感 `juice_*.test.ts`）MUST **零改动**通过；MUST NOT 借本特性放宽或删除其断言。这些套件守护的是相机、插值与事件桥接契约，与资产替换无关，因此不享有「可随本特性更新」的授权。
  - *与 FR-029 的分工*：「逻辑内核与玩法测试零改动」由 FR-029 承担；本条只负责**渲染侧非资产套件**，两条无交集。
- **FR-029**: 既有的**逻辑内核与玩法**测试 MUST 100% 零改动通过（失败 0）。与「资产结构」耦合的测试套件（`tests/assets/*` 与 `tests/render/*_art`）MAY 随本特性更新；更新后全部测试用例的总数 MUST NOT 低于改动前的 893（893 为**下限**）。既有渲染场景图冻结契约的断言 MUST NOT 被放宽或删除。
- **FR-030**: 本特性的视觉覆盖范围 MUST 限定为**局内世界美术**——玩家、全部敌人、地牢 Tilemap 环境、局内特效。界面（HUD、奖励三选一菜单、死亡/胜利/营地覆盖层）与音频资产 MUST NOT 在本特性范围内被改动，MUST 保持现状。
- **FR-031**: 高清动画 MUST 采用**高分辨率逐帧位图序列**（精灵图集）形态。MUST NOT 因本特性引入任何新的运行时依赖——表现层的依赖集合 MUST 与改动前一致。

### Key Entities *(include if feature involves data)*

- **玩家高清形象**：玩家实体的可视代表；关键属性为「动作」「朝向」「显示倍率下的清晰度」，需覆盖待机/移动/攻击/受击（并保留冲刺/死亡）。
- **敌人类别高清形象**：由数据表声明的每一种敌人到专属高清形象的映射。canonical id ↔ 中文标签：`grunt`（普通）· `elite`（精英）· `raider`（突袭者）· `bomber`（自爆者）· `gunner`（远程精英）。关键属性为「类别」「动作」「朝向」「死亡表现」。
- **地牢场景贴图集**：构成房间外观的地面与墙体贴图；关键属性为「与房间网格（墙格/空地/出生点）的对应」「墙体深度表现」。与房间的网格地形一一对应。
- **局内特效资产**：命中火花、冲刺拖尾、危险预警、伤害数字与掉落物的高清资产；关键属性为「元素类型」「应拾取 / 应躲避」的视觉区分。**在本特性覆盖范围内**（FR-030）。
- **界面与音频资产**：HUD、奖励三选一菜单、死亡/胜利/营地覆盖层，以及音频资产 —— **不在本特性范围内**，保持现状（FR-030）。
- **资产清单（本地）**：本特性引入的全部高清资产的登记表，用于启动加载与缺失检测；不含任何远端引用。
- **资产许可登记**：逐项记录每份资产的来源与许可（用于合规审查），确保 100% 可追溯且不含商业游戏专有资产。
- **体积预算**：本特性更新后的资产总量与单文件上限，作为构建期与测试期的硬判定依据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在角色静止、四向移动、攻击、受击、冲刺共 8 种情形下，观察者能在 1 秒内正确说出角色当前朝向与所处动作，成功率 100%。
- **SC-002**: 在 5 种敌人类别两两混合的同屏场景中，观察者仅凭形象（关闭颜色线索）识别类别的正确率 ≥ 90%。
- **SC-003**: 在 5 种敌人类别中，每一种都具备待机/移动/攻击/受击表现的比例 = 100%（逐类别核验）。
- **SC-004**: 可见墙体的边界与实际碰撞边界的一致率为 100%（在任意房间中，视觉上「能走进去」的位置都必须真的能走进去）。
- **SC-005**: 在小型起始房、带柱子的竞技场、30×30 压测房三类房间中，纹理铺设出现拉伸/错位/空洞的房间数 = 0。
- **SC-006**: 在固定的种子与固定输入序列下，改动前后的模拟状态逐 Tick 完全一致（差异处数 = 0），且快照摘要逐位相同。
- **SC-007**: 逻辑内核（`src/`）的改动文件数 = 0（以源码差异实测）。
- **SC-008**: 仓库中低分辨率像素资产、像素派生生成工具与像素源素材包的残留数 = 0；构建产物中旧像素资产残留数 = 0。
- **SC-009**: 在 100%–400% 的显示倍率区间内，观察者判定「角色与地牢画面清晰、无像素块放大、无可见锯齿」的比例 ≥ 90%。
- **SC-010**: 在约 150 个敌人同屏的压测场景下，表现层**每帧耗时中位数**的「改动后 / 改动前」**比值 ≤ 1.2**（同机、同场景、连续 3 次取中位数）。判定 MUST 使用比值，MUST NOT 使用绝对墙钟阈值。
- **SC-011**: 既有逻辑内核与玩法的测试用例 100% 通过（失败 0）；既有**渲染**测试套件中不属于 `tests/render/*_art` 的部分（相机、插值、桥接、打击感）在**未修改**的前提下 100% 通过；既有渲染场景图冻结契约断言在未修改的前提下全部成立；改动后全部测试用例的总数 ≥ 893。
- **SC-012**: 在完全离线的环境下，游戏的全部画面可用，且对外部服务的请求数为 0。
- **SC-013**: 全部资产的许可可被逐项追溯（有明确来源与许可的比例 = 100%），且经审查不含任何商业游戏专有资产。
- **SC-014**: 全部美术资产满足更新后的体积预算：资产总量与单文件均不超过规划阶段确定的上限（构建产物实测）。
- **SC-015**: 在连续 600 帧（约 10 秒）的观察窗口内，玩家与敌人的动画满足：相邻帧间隔超限次数 = 0、空白帧次数 = 0、非终止动作僵直超时次数 = 0（按 FR-006 的五条量化判定逐项计数）。
- **SC-016**: 局内特效与掉落物（命中火花、冲刺拖尾、危险预警、伤害数字、三类掉落物）全部呈现为 HD 资产（残留占位几何处数 = 0），且「应拾取」与「应躲避」两类在视觉上清晰可辨、不混淆。

## Assumptions

- 目标平台仍为桌面浏览器；本特性不引入新的玩法机制、不改动操作方式与数值。
- 逻辑内核（确定性模拟、17 段管道、组件与预制体）被视为**冻结资产**：本特性只在表现层做「状态/事件 → 高清资产」的映射，不修改任何玩法规则或物理参数（对应宪法 Principle I / II / VI）。
- 占位几何不会被删除，而是保留为高清资产缺失时的**回退表现**（沿用既有降级契约）。
- 高清资产以文件形式随应用本地分发并提交到仓库；不引入外部 CDN 或后端服务。仓库体积会相应增大。
- 沿用既有资产接入的两条既有约束：**唯一引用点**（全仓库只有一处模块静态引用资产文件，删文件即构建失败）与**许可合规**（开放许可或本仓库原创，逐项登记）。
- 沿用 M17（`specs/025`）确立的相机缩放与视口自适应语义；本特性不修改该语义，只要求高清资产在该语义下保持清晰。
- 高清资产的**来源**取「开放许可的高清素材库（CC0 / 公共领域 / 明确允许再分发）」或「本仓库原创 / 程序化生成」。若需引入付费或商业授权素材，须另行提出并附授权证明。
- 分辨率目标（基准 tile 像素尺寸、角色显示高度）与**体积预算的具体数值**在规划阶段（`/speckit.plan`）确定；本规格只要求「高清且满足预算」这一可判定性质。
- 敌人形象的分类沿用既有的「能力签名」只读推断方式，不向实体写入类型标签，以免改动快照内容与冻结内核。
- **已裁定的三项范围决策（2026-10-02 用户裁定）**：
  1. **测试处置**：逻辑内核与玩法测试零改动全绿；与资产结构耦合的测试套件（`tests/assets/*`、`tests/render/*_art`）允许随本特性更新，**893 例为下限**。据此，「彻底移除像素资产、像素派生生成工具与像素源素材包」是可达成的目标。
  2. **视觉覆盖范围**：仅**局内世界美术**（玩家、全部敌人、地牢环境、局内特效）；界面与音频不在本次范围内，保持现状。
  3. **动画技术路线**：**高分辨率逐帧位图序列**（精灵图集）；不引入新的运行时依赖。
- **许可口径的收窄与放宽**：既有 `tests/assets/manifest.test.ts` 把每个条目的许可钉死为 `CC0-1.0`。本特性允许将该断言放宽为「**经登记的开放许可白名单**」（CC0 / 公共领域 / CC-BY 等明确允许再分发的授权），以容纳高清素材库的常见授权；但「不含任何商业游戏专有资产」这一底线 MUST 保持（FR-023）。
- **已知风险（须在规划阶段给出缓解）**：
  - **素材可得性风险**：四个朝向、含待机/移动/攻击/受击的**高清逐帧**素材在开放许可库中较为稀缺。缓解方向：优先选用开放许可的高清地牢/角色素材包，缺口以本仓库**原创或程序化生成**补齐，并保持风格统一。
  - **体积预算风险**：高清逐帧资产极易超出既有的 6 MB / 1 MB 预算；预算需在规划阶段重新协商并以构建产物实测（FR-024 / SC-014）。既有 `tests/assets/licenses.test.ts` 的体积断言随本特性更新（FR-029 已授权）。
  - **帧数与内存风险**：四向 × 四动作 × 多帧的高清图集会抬高显存占用与加载时间；需在约 150 敌人同屏的压测下以**比值口径**验证逐帧开销（SC-010），并确认加载不阻塞游戏循环。
