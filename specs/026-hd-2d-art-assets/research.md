# 研究记录：高清 2D 美术与动画资产替换（M18）

> Phase 0 产出。本文件把**规格约束、两位成员的专业结论、用户裁定**收敛为可执行的决策集。
> 成员原始交付物：`design/art-direction.md`（美术总监 · 林绘澄）· `design/engineering-architecture.md`（技术总监 · 程基岩）。
> 全部决策 MUST 可追溯到 `spec.md` 的 FR/SC。

| # | 议题 | 裁定 | 依据 |
|---|---|---|---|

## 3. 决策记录

### D1 · 动画技术 = HD 逐帧位图序列
- **决策**：全部角色/敌人/特效使用高分辨率精灵图集；不引入骨骼动画运行时。
- **理由**：用户裁定（S2）。零新增依赖 ⇒ 不触碰宪法「`client/` 仅 pixi.js + howler」条款；可沿用既有 `SHEET_DATA` schema 与 `<spriteId>.<action>.<facing>` 命名契约，改动面最小。
- **备选**：Spine 骨骼（内存效率与插值更好，但需新依赖 + 修订技术栈条款 + 重写资产结构断言）；混合方案（维护两套加载路径，复杂度最高）。均被否决。

### D2 · 基准 tile = 128 × 128
- **决策**：`TILE_NATURAL_PX` 由 `16` 改为 **128**；1 世界单位 = 1 格 = 128 自然像素，渲染缩放为 `PX_PER_UNIT / TILE_NATURAL_PX = 10/128`。
- **理由**：用户裁定（P1）。约束链：`PX_PER_UNIT = 10`、M17 的 `z ∈ [1,16]`（`ZOOM_FIT_MARGIN = 0.8`），房间短边恒占视口短边 80%。在此链下 128 使**所有**现实场景的放大倍率 ≤ 2.5×。
- **备选**：64（体积最小、可直接用 CC0 64px 素材包，但起始房 @DPR1 即需 1.35× 放大、@DPR2 需 2.7×，锐利余量最小）；256（pixel-perfect 但体积 ≈4×、CC0 库无 256px 地牢素材，需全量重绘）。

### D3 · 体积预算 = 3 MB / 12 MB + 三个新维度上限
- **决策**：单文件 **≤ 3 MB**、总量 **≤ 12 MB**、单图集像素 **≤ 4096×4096**（目标 ≤ 2048×2048）、图集数 **≤ 12**。
- **理由**：用户裁定（P2）。估算模型 `字节 ≈ 帧数 × W × H × B/px`，`B/px ∈ [0.5, 0.75]`；全量最坏 ≈ 9.64 MB。放宽单文件上限（1 MB → 3 MB）时**同步新增**图集像素上限与图集数上限两条等价强度约束，避免断言退化（`contracts/hd-asset-manifest.md` §6 / VR-24）。
- **备选**：4 MiB / 32 MiB（工程总监口径，余量 ~3× 但断言几乎失去约束力）；4 MB / 16 MB（折中）。
- **落点**：`tests/assets/licenses.test.ts` 的体积断言改写。

### D4 · 掉落物资产 = `fx.pickup.*`
- **决策**：金币 / 治疗 / 暗影三类掉落物的资产 id 迁到 `fx.` 命名空间（如 `fx.pickup.gold` / `fx.pickup.heal` / `fx.pickup.darkness`）。
- **理由**：用户裁定（P3）。掉落物渲染在**世界空间**，与 HUD 的屏幕空间图标是两回事；分属不同命名空间让「FR-030：`ui.*` 不动」成为一条可机器检查的边界。
- **影响**：`sprite-map.ts::pickupIconId` 的返回值随改；`manifest.ts` 新增条目；`fx_art.test.ts` 的剪影用例随改；许可登记同步。
- **备选**：复用 `ui.icon.*`（零新增，但世界元素挂 UI 命名空间，与 FR-030 边界自相矛盾）。被否决。

### D5 · 动作 × 朝向矩阵 = 全量
- **决策**：玩家 4向 × 6动作（idle/move/dash/attack/hit/death）；六类敌人各 4向 × 4动作（idle/move/attack/hit）；`death` 为通用消亡表现。
- **理由**：用户裁定（P4）。FR-002 要求玩家四向；FR-005 要求敌人具备四动作且朝向与模拟层一致。全量是唯一无歧义满足两者的方案。
- **作画量**：玩家 148 帧；敌人合计约 552 帧（美术总监附录 A 明细）。
- **风险与缓解**：作画量为最高风险（美术总监 R3）。缓解：程序化派生骨架 + 人工精修关键帧；左右向可镜像（须保证非对称装饰不穿帮）；敌人 `dash` **别名 `move`**（见 D6）。

### D6 · 敌人 `dash` 别名 `move`
- **决策**：敌人图集不为 `dash` 单独作画，`enemy.<type>.dash.<facing>` 指向 `move` 的同名帧序列。
- **理由**：美术总监 Q5 建议。敌人冲刺非核心表现；别名满足命名契约的**键存在性**（`tests/assets/manifest.test.ts` 需要该键存在），同时省去每类 16 帧。
- **备选**：独立作画（+96 帧，收益低）。

### D7 · 纹理过滤 = 全局 `nearest` 保持 + HD 按纹理 `linear` + mipmap
- **决策**：`AssetCatalog.load()` 开头**仍设** `TextureSource.defaultOptions.scaleMode = 'nearest'`；随后对每个 HD 世界美术纹理的 `TextureSource` 显式设 `scaleMode = 'linear'` 与 `autoGenerateMipmaps = true`。
- **理由**：M17 的 `tests/render/camera_zoom_sharpness.test.ts` 以**字面量** `'nearest'` 钉死全局默认，且该文件**不在** S1 授权的 `tests/render/*_art` 集合内。按纹理覆盖使 M17 冻结测试**零改动**继续通过，同时满足 FR-025（HD 在放大下清晰）。mipmap 消除**缩小**时的摩尔纹（30×30 房 `z=2.88`、DPR1 时 128px → 29px，缩小 4.4×，无 mipmap 必现摩尔纹 ⇒ 违反 SC-009）。
- **备选**：全局改 `'linear'`（须把授权范围扩到 `camera_zoom_sharpness.test.ts`，撕毁 M17 冻结契约）。被否决。

### D8 · 图集 gutter ≥ 4px
- **决策**：图集内相邻帧之间 MUST 留 ≥ 4px 透明 gutter。
- **理由**：mipmap 在低层级会跨帧取样，无 gutter 会出现帧间渗色（atlas bleeding）。2048² 图集尤其重要。

### D9 · 墙体深度 = autotile + 「格内三带」，不外溢
- **决策**：墙体拆为**顶面 cap（~55%）/ 立面 face（~43%）/ 墙脚阴影（~2%）**，全部落在**墙格内部**；部件按邻接位掩码选择（8 邻 → 47 部件；4 邻 → 16 例）。**立面 MUST NOT 向可通行格延伸**。
- **理由**：这是「视觉边界 == 碰撞边界」（FR-008 / SC-004，一致率 100%）的**构造性**保证 —— 像素不外溢墙格，视觉与碰撞在几何上同一。同时 FR-010（不遮挡可通行地面）自动成立。
- **备选**：立面外溢到相邻格以营造更强的立体感 —— **明确否决**：它会让「看起来能站」的位置其实被阻挡，直接违反 FR-008。

### D10 · 场景图 = 零新增节点
- **决策**：墙体深度**落在既有 wall node 内部**（wall node = `Container`，内部含顶面/立面子精灵）。MUST NOT 新增常驻层。
- **理由**：`tests/render/tilemap_art.test.ts` 断言 `staticLayer.children.length === 1 + wallCount`，且渲染场景图 6 条冻结契约（F1–F6）中「无墙时 `camera.children` 长恰 1」会被任何常驻节点撞坏（FR-027）。深度内嵌于 wall node 使 `staticLayer` 的**子节点数**不变。
- **代价**：`tests/render/tilemap_art.test.ts` 中「wall node 的子节点数 == cols×rows」这条断言随实现更新（属 `*_art`，已授权）。

### D11 · `fx.spark` 保持 `Graphics`
- **决策**：火花粒子**不**升级为 `AnimatedSprite`；HD 质感落在纹理填充与绘制参数上。
- **理由**：`tests/render/fx_art.test.ts` 显式守护「frozen particle contract」（每个 spark 必须是 `Graphics`）。这是既有的**设计决策**而非偶然断言，MUST NOT 撕毁。
- **边界**：HD 化作用于非粒子元素（拖尾、危险预警、掉落物、伤害数字）。

### D12 · `AnimationState` 不扩展
- **决策**：保持 6 个动作（`idle`/`move`/`dash`/`attack`/`hit`/`death`）。不新增动作，不新增 `ActionState` 枚举成员。
- **理由**：新增动作会要求改 `src/` 的状态枚举与 17 段管道（FR-003 / FR-011 / FR-014）。HD 美术的动作需求已被既有 6 动作覆盖。

### D13 · 循环语义
- **决策**：`idle` / `move` **循环播放**；`dash` / `attack` / `hit` / `death` **停在末帧**。
- **理由**：FR-006 要求待机与移动为循环动作、攻击与受击有明确起止。动画时钟由 ticker 的 `deltaMS` 驱动（视觉时钟，MUST NOT 由逻辑 tick 推导，ADR-002）。

### D14 · 尺寸换算由纹理实际尺寸推导
- **决策**：精灵缩放由 `hurtboxSpriteScale(radiusUnits, naturalPx, pxPerUnit)` 计算，`naturalPx` 取 **128**（HD 基准）；并**新增一致性断言**确保 `TILE_NATURAL_PX` 与图集 `meta.tilePx` 一致。
- **理由**：FR-008 要求「视觉尺寸 == 碰撞尺寸」；由 hurtbox 半径推导（而非手调常数）使该性质在数值再平衡时自动成立。新增一致性断言防止常量与图集漂移。

### D15 · 图集切分 = 按装载单元
- **决策**：世界 HD 图集按**装载单元**切分（player 1 张、每个敌人类型 1 张共 6、tiles 1 张、fx 1 张 → 共 9 张）；`AssetCatalog` 的**按 `source` 去重**逻辑零改动。
- **理由**：`AssetCatalog` 已按 `source` 去重（六类敌人曾共享一张 `enemies.png`）。按类型切分使去重语义自然，且单张图集尺寸可控（目标 ≤ 2048²）。
- **备选**：按动作切分（美术总监原案 10 张，含 player-a/b/c）—— 在 `tilePx = 128` 下玩家 148 帧 × 128² ≈ 1552²，单张可容纳，故按装载单元切分更简单。

### D16 · 敌人分类 = 保持能力签名只读推断
- **决策**：`sprite-map.ts::enemyTypeFromSignature` 的**优先级表原样保留**（armor+hazard → gunner；armor → elite；hazard → bomber；AI → raider；其余 → grunt）。
- **理由**：向实体写入「类型标签」会进入 `listComponents()` ⇒ 改变 `snapshot()` 摘要 ⇒ 破坏确定性与冻结内核。该表已由 `tests/assets/sprite-map.test.ts` 冻结，**MUST NOT 放宽**。
- **已知限制**：非 `grunt` 的精英变体按基础类型呈现（沿用 spec 024，并在本特性中保持）。

### D17 · 许可白名单
- **决策**：白名单 = `['CC0-1.0', 'Public Domain', 'CC-BY-4.0']`，以**显式字面量列表**声明（禁止空真断言）。**默认排除** GPL 与 CC-BY-SA（传染性/义务）。
- **理由**：美术总监 D.3。底线不变：MUST NOT 含商业游戏专有资产；保留 `/Supergiant/i` 断言并 SHOULD 扩展为已知发行商名单；MUST NOT 使用无再分发授权的同人素材。
- **例外**：仅当某必需资产只能以 CC-BY-SA 获取时才启用，并在 `LICENSES.md` 逐条注明义务。

### D18 · 素材来源 = 混合三源
- **决策**：**环境**采用 Screaming Brain Studios *Top Down Dungeon Pack*（**CC0**，64×64，含完整 autotile）并**本仓库重绘至 128**（登记 modifications）；**角色/敌人基底**采用 CC0 非像素角色包（OGA）的形态与朝向，**其余动作由本仓库 HD 重绘**；**特效 / 掉落物 / 伤害数字字形**为**本仓库原创 / 程序化生成**。
- **理由**：FR-023 已授权「开放许可 **或** 本仓库原创 / 程序化生成」。诚实披露的缺口：**4 向 × 6 动作的高清角色与 5 类差异化敌人，在 CC0 库中几乎不存在**（美术总监 D.2 缺口表）。程序化派生结果属本仓库原创变换，许可安全（与既有 `build-atlas.py` 的做法同源，只是 HD 化）。
- **排除**：LPC / FLARE（CC-BY-SA / GPL，传染性）；DCSS tiles 的 unknown-license 子集。

### D19 · SC-008 口径 = 「在范围内的世界美术」
- **决策**：SC-008「低分辨率像素资产残留数 = 0」解释为**在范围内（局内世界美术）的像素资产**：`assets/art/atlas/**`、`assets/art/raw/**`、`assets/art/tools/build-atlas.py`。
- **保留并显式登记**：`assets/art/ui/*.png`（界面贴图）与 `assets/audio/**` 依 FR-030 **保留**，在验收报告中登记为「FR-030 授权保留」，不计入 SC-008 的残留数。
- **理由**：FR-030 明确界面与音频不在范围内；若不显式登记口径，SC-008 会与 FR-030 相互矛盾。

### D20 · 性能口径 = 交错比值 ≤ 1.2
- **决策**：复用既有 `tests/performance/render_art_cost.test.ts` 的**交错比值**方法；约 150 敌人同屏下每帧耗时中位数比值 ≤ 1.2；连续 3 次取中位数。
- **理由**：宪法 Principle IV 禁用绝对墙钟阈值（实测漂移可达 2×）。
- **补充**：HD 图集加载 MUST NOT 阻塞游戏循环（FR-022）。

### D21 · 无损证明 = 摘要逐位相同
- **决策**：以固定种子（`0x12345678`）跑 601 tick，比较 `listEntities() × listComponents()` 拼串过 FNV-1a 的摘要；基线值 **`f52dfdd4`**（M15/M16/M17 同值）。
- **理由**：宪法 Principle IV —— **既有测试全绿 ≠ 无损**（M15 实测：类型错误让全部 634 例通过而摘要从 174 变 198 实体）。两个 lossless 套件 MUST 零改动继续绿。

### D22 · 「减少动态效果」降级 = 可选增量，延后
- **决策**：不在本特性主线实现；登记为后续可选增量（降 `frameMs` 倍率 + 关 additive 拖尾）。
- **理由**：规格 Edge Case 列为可选；不阻塞主线交付。

## 4. 两位成员的冲突与仲裁
