## 关键技术决策
1. **Tick 精度**：`fixedDeltaSeconds = 1/fps`、`tickDurationMs = 1000/fps`（**不截断**）；`elapsedSeconds = totalTicks * fixedDeltaSeconds`（乘法，非浮点累加）。→ 60 ticks 严格 === 1.0s。**禁止硬编码 16.67ms**（60×16.67=1000.2ms 会破坏确定性）。
2. **输入契约**：事件绑定目标 tick；`step()` 每步先 drain 当前 tick 输入 → 跑系统 → 时钟 +1。同 tick FIFO。非法 tick / 已过 tick 抛 `RangeError`，tick=0 合法。
3. **Snapshot 不可变**：深拷贝 + 递归 `Object.freeze`，与实时 world 零引用共享。
4. **ECS**：类式组件 + World 以构造函数为键的 Map；`query`/`listEntities` 按 id 升序、`listComponents` 按类型名排序 → 全程确定性。
5. **零运行时依赖**：`dependencies: {}`，仅 devDeps（typescript / vitest / @types/node）。

## 踩过的坑（M1+ 必读）
1. **npm 锁文件是平台相关的**：项目内已有 `node_modules` 时，`npm install --package-lock-only` 只会解析出**当前平台**条目（本项目曾出现 rollup/esbuild 平台包条目全缺）。修法：在**无 node_modules 的隔离目录**生成锁文件再采纳，并做「逐包比对（移除 0 / 版本不一致 0）」。
2. **`npm ci` 严格锁文件驱动**：锁文件缺 optional 平台包时 `npm ci` **不报错（exit 0）**，但会**静默跳过**，导致原生二进制缺失 → vitest `MODULE_NOT_FOUND`。判定方法：`complete/` vs `stripped/` 两份锁文件各跑 `npm ci --dry-run`，比对包数（实测 94 vs 92）。
3. **vitest 必须用 `pool: 'threads'`**：默认 forks 池在本环境写系统 Temp 被拒（EPERM）。CI 需保留此设置或确认 Temp 可写。
4. **Windows esbuild postinstall EBUSY**：首次 `npm install` 可能中断，注意事后校验平台包是否齐全。

- `npm run typecheck` → 零错误；CI 纯逻辑静态门本地重放 → OK
- QA 证伪性检查：把管道顺序改为 `[State, Dash, Movement]` → **10/18 失败**，证明断言对管道顺序敏感（非空转）

## 关键技术决策（M1-T03+ 必读）
1. **管道顺序是硬契约**：`MovementSystem → DashSystem → StateSystem`。
   - Movement 先跑 ⇒ 按**上一 Tick 的状态**积分 ⇒ 本 Tick 启动的冲刺从**下一 Tick**才位移 ⇒ 15 Tick 冲刺恰对应 15 个位移 Tick。
   - StateSystem 最后跑 ⇒ 冲刺决策就位后才推进 `ticksInState` ⇒ 无敌窗口与冲刺前段对齐、第 15 Tick 精确退出。
   - **重排会破坏 QA 的逐 Tick 断言**。
2. **冲刺方向锁定的实现**：不覆写 `InputComponent`，而是 `startDash` 把 `(cos θ, sin θ)` 写进 `VelocityComponent.directionVector`；`MovementSystem` 的 DASHING 分支只读该向量、**不读 `moveVector`、不重算 `facing`**。
   好处：既满足 AC-02（中途输入不转向），又**不吞掉玩家按住的方向**，冲刺结束可立即续走。
3. **计时全部落在组件字段**（`ticksInState` / `cooldownRemaining`），系统**零跨 Tick 隐藏状态**（spec 00 §6.1）。
4. **冷却自「冲刺开始」计 30 Tick**：DashSystem 非 DASHING 分支「先递减、后判 `=== 0`」⇒ 恰在 tick 30 归零；按住冲刺键会在 tick 30 **自动再冲**（电平语义，非边沿）。
5. **无敌窗口的精确边界**：判定 `ticksInState < invulnerableTicks` ⇒ 每步 `step(1)` 后**时钟 1..12 无敌为真、13..15 为假**。
   推导时最易踩的坑是「**时钟 N vs tick N**」错位：注入在 tick 0，时钟 N 表示「已处理完 tick N-1」。改时序契约前先画这张表。
6. **标签用自由函数而非组件方法**：守住「组件为纯 POD、不含行为」契约。`addTag` 对缺 `TagComponent` 的实体**惰性创建**；`hasTag` 缺组件返回 false。
7. **前置修正 `clampMagnitude`**：M1-T01 的「归一化」改为「限幅」，支持摇杆半推慢走；M1-T01 的 AC-03 用例仍全绿（(1,1)/(3,4) 限幅后仍是单位向量）。

## 关键设计决定
1. **管道扩展为六段（M1 三段顺序不动）**：`Movement → Dash → State → CombatAction → Collision → Lifespan`。
   `Lifespan` 必须**最后**，否则判定圆少一个 Tick 有效窗口。
2. **判定圆是独立实体**，只在生成时取一次世界坐标（不跟随攻击者），寿命以 `activeTicks` 计。
3. **圆相交用平方距离**（`dx²+dy² < (r1+r2)²`）：省开方、只用 `+ * <`，跨平台确定性更好。
4. **无敌帧消费契约 = 整体忽略**：`hasTag(Invulnerable)` 时**不结算伤害且不写入 `hitEntities`**。
   若写入账本，该目标会对本次攻击永久免疫 —— 这是本任务最容易写错的一点。
5. **冲刺改上升沿**：`DashSystem` 读 `buttonDashJustPressed`；长按不再于冷却结束瞬间自动连冲。
   上升沿由 `MovementSystem.bindInput` 用「按键集合的转移」推导，电平字段行为保持不变。
6. **`spawn-helpers.ts` 消除预制体重复**：玩家/敌人组件集完全相同，只有阵营不同。

## 踩过的坑
- **CI 正则收窄后仍误伤**：`\bwindow\.` 会命中句末的英文名词 `window.`（我在 `pipeline.ts` 注释里写了
  "activeTicks window." 导致本地门控 FAIL）。**残留缺陷**：该正则只是把误伤面从「任意 window 单词」缩到
  「后跟句点的 window」。根治需用 `globalThis\.window|window\.(document|location|navigator|...)` 之类更精确的形态，
  或干脆排除注释行。当前对策：`src/` 注释继续避免该词面量。
- **测试 tick 语义**：`step(n)` 处理的是 tick `0..n-1`，断言时容易差一拍（无敌帧窗口的最后一拍是 tick 12，
  伤害落在 tick 13）。写逐 Tick 断言时务必先算清「step 几次 = 处理到哪个 tick」。
- **判定圆在自己连接的 Tick 末被销毁**：`LifespanSystem` 在 `CollisionSystem` 之后跑，所以命中发生的那一拍
  结束后实体已消失，断言不能再 `getComponent(hitbox)`。对策：在上一拍先快照判定圆坐标，或用 `distanceToPoint`。
- **全局输入帧的交叉响应**：输入帧是全局的，玩家与敌人会同时响应同一按键（敌人因此也必须持 `InputComponent`）。

## 关键设计决策（跨会话必读）

### 1. `ModifierContext extends SystemContext`（不要改成往 SystemContext 里塞字段）
`IModifierHandler.onHit(event, context)` 需要 `World`，但 spec 05 C6 禁止改 `SystemContext`。
解法：`ModifierContext` 是 `SystemContext` 的**结构化超集**（多一个 `readonly world: World`）。
`GameSimulator.step` 与通用仿真核零改动，且签名语义仍是 `onHit(event, context)`。

### 2. DoT 相位用「管道位置」解决，**不用** `+1` 补偿（M3-T02 最重要的架构结论）
`StatusEffectSystem` 排在 **`CollisionSystem` 之后、`ModifierSystem` 之前**（第 8 段）。
因为状态是在 `ModifierSystem` 里施加的，排在它之前 ⇒ 施加当 Tick **不走**状态时钟：
- 第 k 次结算 = `T + k × intervalTicks`；摘除 = `T + durationTicks`（Tick 末）
- **字段值 == 常量值**（`ticksUntilProc` 就是 `intervalTicks`），快照断言无需心算偏移

若排在 `ModifierSystem` 之后，每个数字都会静默少 1（首次结算 `T+29`、摘除 `T+119`）。
**这是与 `applyFreeze` / `HITSTUN` 的 `+1` 补偿不同的另一条路线**，两者并存但不要混用：
判定圆 / 顿帧 / 硬直仍走 `+1` 补偿（它们的相位无法靠挪位置解决），状态时钟走位置。

### 3. DoT = 真实伤害 = 只调 `applyDamage`
不生成判定圆、不抛 `HitEvent`、不写顿帧 / `HITSTUN` / `KnockbackComponent`、**不做冻结门控**、
**不检查无敌帧**。理由：写 `KnockbackComponent` 会覆盖清零基础命中的击退；
进 `HITSTUN` 会变成每 30 Tick 一次的硬直锁；抛事件会让 DoT 触发 `OnHit` 类祝福。
QA 断言：顿帧观测集恰为 Tick `1..4`、`HITSTUN` 恰为 `1..11`、150 Tick 内**仅 1 条 `HitEvent`**。

### 4. 结算先于到期判定
`if (ticksUntilProc <= 0) { proc; reload }` 必须在 `if (remainingTicks > 0) keep` **之前**，
否则 `duration = k × interval` 时第 k 次结算静默消失。约定 `durationTicks` 取 `intervalTicks` 整数倍。

### 5. 注册表分派的三步门序（不可交换）
`sourceModifier !== null` → 遍历攻击者 `ModifierComponent.modifiers`（升序）→ `registry.get(id)?.onHit(...)`。
未知 id **静默跳过**（数据表可引用本构建未附带的祝福）；重复注册 **抛 Error**；
`createDefaultModifierRegistry()` 每次 `createDefaultSystems()` 建**新实例**（同 `EventQueue` 隔离规则）。
`drain()` 为空时**连 `ModifierContext` 都不构造**（C9 严格无操作）。

## 关键决策（改代码前必读）
1. **管道 10 段 → 11 段**：`PlayerControllerSystem → FreezeSystem → **AISystem** → MovementSystem → …`。
   `AISystem` 插在 **`FreezeSystem` 之后**，而不是「最前」。理由：`FreezeSystem` 先递减 `remainingTicks`，
   其后所有系统按**递减后**的值判断本拍是否冻结；`AISystem` 若排在它之前，顿帧**恢复拍**会与运动系统错开一拍
   （敌人比玩家晚一拍恢复）。这是**相位契约**，不是风格问题。任务书说「极前端」——它在**意图生成段**
   （仍早于所有推进系统），但为相位正确让位于 `FreezeSystem` 之后。spec 07 §5.2 规则 2 / §10 取舍 1 已登记。
2. **AI 的朝向锁定走 `IntentComponent.aimRadians`**，不直接写 `TransformComponent.facingRadians`——
   否则会出现两个 `facingRadians` 写入者，且违反 AC-01「AI 的输出仅仅是修改 `IntentComponent`」。
   `MovementSystem` 只在**静止**分支应用它（移动时朝向仍由移动方向决定，M1 契约不变）。
3. **AI 是「可选能力」，`EnemyFactory.spawn` 默认不挂 `AIControllerComponent`**。默认挂载会当场覆写
   M1–M3 全部「手写敌人意图」用例的意图 → 大面积回归。要 AI 必须显式传 `ai`（spec 07 C10）。
   `ai` 与 `hardwareInput` 互斥，同时给出 **抛 `RangeError`**。
4. **顿帧 = 暂停（不吞帧），硬直 = 打断（作废计划）**，且**门控顺序不可交换**（先判顿帧、后判硬直）。
   同一次命中同时写 hitstop + HITSTUN，若先判硬直，顿帧窗口内就会把 FSM 重置，「暂停」被降级成「打断」。
5. **进入前摇那一拍不递减 `ticksRemaining`**（`enterWindup` 后 `break`）：前摇恰为 `windupTicks` 拍，
   出手落在「进入拍 + `windupTicks`」。
6. **冷却结束只回决策态**（`CHASING`/`IDLE`），不直接进 `WINDUP` ⇒ 出手周期 = `windupTicks + cooldownTicks + 1`。
7. **「发现」拍不移动**：`IDLE → CHASING` 的那一拍只翻状态、不输出移动向量，追击从下一拍开始。
   这给敌人 1 Tick 反应延迟，也让 `IDLE` 与 `CHASING` 行为真正不同（否则两态退化成别名）。
   **AC-03 的判据是「`CHASING` 状态下输出归一化向量」**；但 `IDLE` 的 `dist ≤ attackRadius` 分支**无**延迟。
8. **`wantsToAttack` 是单 Tick 脉冲且同拍被 `CombatActionSystem` 消费**，所以断言它必须把探针
   **插在 `AISystem` 正后方**（`[...base.slice(0,3), probe, ...base.slice(3)]`，并以 `base[2].name === 'AISystem'` 钉住插入点）。
   判定圆在**出手同拍**生成（不是下一拍），并在下一拍仍存活。
9. **自动索敌**：`targetEntityId` 为空或已死时取最近敌对存活实体，`query` 升序 + **严格 `<`** ⇒ 等距取较小 id。
