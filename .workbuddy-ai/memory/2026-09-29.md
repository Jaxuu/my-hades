### 关键发现 2（P0 缺陷，已修）：尸体视图会被「复活」，死亡效果无限重播
**根因**：`createMissingViews` 只以 `world.query(TransformComponent)` 为依据建视图。但 M4-T02 铁律是
**尸体永不销毁**（spec 08 §4.4）⇒ 尸体仍 `isAlive`、仍有 `TransformComponent`
⇒ 死亡 FX 播完 `recycle` 删掉视图后，**下一帧立刻为这具尸体重建视图**，`syncTransforms` 又看到
`isDead` → `isDying = true` / `deathElapsedMs = 0` → FX 从头重播，周期 = `DEATH_FADE_MS`（400ms）**无限循环**。
表现：方块每 400ms 闪回一次，直接违反验收标准「打死方块后方块消失」。

**复现手法（值得复用）**：`pixi.js` 的**场景图对象（`Container` / `Graphics`）在 node 下可正常构造**，
不需要 jsdom、不需要真浏览器——只需给 `Application` 一个鸭子类型替身
`{ stage: new Container(), ticker: { deltaMS: 20, add(){}, remove(){} } }`，即可用真实 `GameSimulator` +
真实 `GameRenderer` 逐帧驱动并观测 `renderer.viewCount`。
缺陷签名极其清晰：`2,2,…,2,1,2,2,…,2,1`（每 20 帧 = 400ms/20ms 循环一次）。

**修法**：`GameRenderer` 引入 `private readonly retired = new Set<EntityId>()`，
`createMissingViews` 对退役 id `continue`；**只在「死亡 FX 播完」这条路径退役**
（`advanceDeaths` 里 `retired.add(id)` 再 `recycle`）。
**关键取舍**：`recycleDestroyed`（`destroyEntity`，如判定圆寿命耗尽）**不退役**——那条路径自纠正
（已销毁实体不再出现在 `query` 里），而万一将来 id 被复用，误退役会**永久隐藏一个合法实体**，是更糟的失败模式。
⇒ 该 `Set` 的安全性依赖 **`World.nextId` 单调递增、id 永不复用**这个不变式，注释里已写明。
修复后 60 帧序列收敛为 `2,…,2,1,1,1,…`。

### 工程要点
- **`vite` 被钉在 5.x**：不是随意选择——`vitest@2.1.8` 的 peerDependency 是 `vite ^5.0.0`，
  装 vite 8 会造成 peer 冲突。⇒ 未来升级 vitest 时才能一起升 vite。
- **`pixi.js` 是 8.21.0**，API 与 v7 差异极大：`await app.init({...})`、画布是 **`app.canvas`**（不是 `app.view`）、
  `Graphics` 是链式 API（`g.circle().fill().stroke()`，**没有** `beginFill/drawCircle/endFill`）。
- **根 `tsconfig.json` 不能塞 `client/`**（根 `lib` 只有 `ES2022`，无 DOM）；新建 `tsconfig.client.json`

- **`GameLoop` 时序**：累加真实 `deltaMS`，`while (acc >= sim.tickDurationMs && steps < 5) { input.flush(sim); sim.step(1); acc -= sim.tickDurationMs; }`。
  **注入必须在 `step` 之前**——`inject` 对 `tick < sim.tick` 抛 `RangeError`，而 `step(1)` 处理的正是 `sim.tick`。
  **必须用 `sim.tickDurationMs`**，不得硬编码 16.67。溢出（`steps === 5`）时清空累加器，防螺旋死亡。
- **`PX_PER_UNIT = 10` 是渲染层唯一持有的常量契约**；`src/` 中不存在任何像素概念。
- **朝向不翻转符号**：`facingRadians` 是 atan2 约定，世界 y 直接映射屏幕 y（向下）时
  `container.rotation = facingRadians` 可直接用。

### 新增铁律（M5-T02 起）
1. **管道现在是 14 段**：`TransformSnapshotSystem` 位于 **index 0**（先于 `PlayerControllerSystem`），
   其余 13 段相对顺序一字未改，`LifespanSystem` 仍 LAST。改管道会打断 **6 处钉桩**：
   `tests/combat/feedback.test.ts`、`tests/ai/enemy_fsm.test.ts`、`tests/combat/boons.test.ts`、
   `tests/combat/status_effects.test.ts`、`tests/combat/death_and_encounter.test.ts`（5 处 `toEqual` 名数组）
   + `enemy_fsm.test.ts` 的探针插入点。**探针插入点一律按名 `findIndex` 定位，禁硬编码索引。**
2. **`PreviousTransformComponent` 是「渲染支撑组件」**：只由 `TransformSnapshotSystem` 写、只由渲染层读，
   **任何玩法系统不得读或写**。丢弃它不改变模拟结果。它**惰性挂载**（首次见到实体以当前 Transform 播种），
   ⇒ `spawnCombatant` 的组件契约不需要改，运行中生成的判定圆也自动覆盖。
3. **插值语义**：`syncWorld(world, alpha)`，`alpha` clamp 到 `[0,1]`；
   `renderX = (prevX + (currX - prevX) * alpha) * PX_PER_UNIT`；rotation 走 `shortestArcDelta`（值域 **`[-π, π]` 两端都闭**，`-π ≡ π`）。
   **`alpha` 默认 `1`** 是刻意的向后兼容选择——`alpha = 1 ⇒ renderX = currX`，逐位等价 M5-T01，
   所以冻结的 `renderer_bridge.test.ts` 单参调用原样通过。
4. **`GameLoop` 的 alpha**：追帧 `while` 循环**之后**（累加器已扣减）算
   `alpha = clamp(accumulatorMs / tickDurationMs, 0, 1)`。累加器余数 = 已走进下一 Tick 的进度 = 插值系数。
   插值带来恒定 **+1 Tick（≈16.7ms）视觉延迟**，是 ADR-002 的显式取舍。
5. **`fxLayer` 必须是 root 的最后一个子节点**：`init()` 先挂 `fxLayer`，实体视图用
   `addChildAt(view, children.length - 1)` 插到它**之下** ⇒ FX 画在最上层，同时保住
   `root.children[0]/[1]` 升序实体视图的 M5-T01 冻结索引契约。**不要改成 `addChild`。**
6. **受击闪烁用 `tint`，不是新系统**：`isFrozen(world,id) || state === ActionState.HITSTUN` ⇒
   `container.tint = 0xff0000`，否则 `0xffffff`。PixiJS `tint` 是**乘法**、只能变暗/移色相，
   **无法"变白"**（白色恰是 NO_TINT）——所以选了纯红。判定圆无 State/Freeze ⇒ 不被染色。
   染色逻辑在 `syncTransforms` 的 `isDying` 提前 `continue` **之后**，不会与死亡 FX 抢 `tint`。
7. **伤害跳字**：`EntityView.lastHp` 在**视图创建时播种**（否则首帧误报）；每帧 `hp < lastHp` ⇒
   生成 `-(lastHp - hp)`，挂 `fxLayer`，`FLOATING_TEXT_LIFETIME_MS = 1000` 后销毁。
   HP **上升**（治疗）不得触发。跳字用真实帧时间推进，**不得回流逻辑层**。

  是 `Container` 子类，`addChild` / `destroy()` 正常。
- ⚠️ **读 `.width` / `.height` / bounds 会抛 `document is not defined`**（惰性文本测量需要 canvas）。

## M7-T01 · 空间边界、投射物与撞墙机制（Wall-Slam） ✅ 336 用例

**交付**：`specs/13_arena_and_projectiles_spec.md`（新）· `src/core/math.ts::resolveCircleAABB` · `components/WallComponent.ts`（新）· `components/ProjectileComponent.ts`（新）· `HitboxComponent.{destroyOnHit,destroyOnWall}` · `PlayerInputComponent`（`CAST_KEY`/`buttonCast*`）· `IntentComponent.wantsToCast` · `MovementSystem`（自驱积分 + 静态几何解算）· `PlayerControllerSystem` / `FreezeSystem` / `DeathSystem` / `CombatActionSystem` / `CollisionSystem` 扩展 · `tests/core/math.test.ts`（新 23）· `tests/physics/walls_and_projectiles.test.ts`（新 28）。test/lint/typecheck 全绿，**零回归**（M0–M6 的 285 用例逐字不动）。

### 铁律级结论（后续必须遵守）
- **管道仍是 15 段，本里程碑零新增零重排**。任务书允许「`MovementSystem` 或紧随其后的 `PhysicsResolutionSystem`」，**选了前者**：`MovementSystem` 的尾部是唯一「本拍位移已完、碰撞测试尚未跑」的位置，加第 16 段只会把 6 处管道钉桩（`feedback`/`boons`/`status_effects`/`death_and_encounter`/`armor_and_dash`/`enemy_fsm` 的 `toEqual` 名数组）全部打散，零行为收益。**这是本工程处理「新增空间/物理相位」的既定落法：扩展 `MovementSystem`，不要新增段。**
- `MovementSystem` 三相位：① `integrate`（意图驱动，M1 逐字不变）② `integrateKinematic`（`ProjectileComponent` 自驱，`transform += directionVector * maxSpeed * dt`，用 `maxSpeed` 而非 `currentSpeed`）③ `resolveWalls`。**相位顺序即契约**：解算在 index 4 < `CollisionSystem` index 8 ⇒ 撞墙销毁的投射物当拍不可能被碰撞测试（不穿墙）。
- **墙体解算目标集 = `TransformComponent` + `VelocityComponent` + 有圆体半径**（`circleBodyRadius`：优先 `Hurtbox`，否则 `Hitbox`）。静止判定圆（近战/Zeus/Poseidon）无 `Velocity` ⇒ **不参与**解算（它们不会"走"进墙里）。**不查冻结、不查硬直**（解算 = 几何不变量，不是动作；冻结相位已保证冻结体不会新产生穿透）。**查 `isDead`**（尸体不位移 ⇒ 也不反穿透）。
- **逐墙顺序推出**（不是把多面墙推量求和）：每面墙重读**已更新**坐标 ⇒ 墙角单趟收敛，无需迭代。遍历顺序 = 实体 id 升序 + 墙 id 升序（确定性）。
- `resolveCircleAABB` 三段：分离（`distSq >= radius²` ⇒ `[0,0]`，**严格 `<` 才算重叠**，贴边不算碰）→ 圆心在盒外（沿最近点向量推 `radius - dist`）→ 圆心在盒内/边界（`distSq === 0` ⇒ 取**最近面**推出，平手按 `-x,+x,-y,+y` 先到先得）。**圆心必须查有限性**：`NaN` 圆心会让 `NaN >= radius²` 为 `false`，掉进包含分支返回 `NaN` 毒值（`NaN > 0` 也是 false）——这是真实可达漏洞，不是保险。
- **撞墙三条件**：`pushed` ∧ `state === HITSTUN` ∧ `KnockbackComponent` 非零 ∧ `dot(push, kb) < 0`。三个写：`applyDamageWithArmor(12)` + `ticksInState = 0`（刷新）+ `kb.velocity = (0,0)`（**墙吸收击退**）。
  - **必须要求 `HITSTUN`**：`KnockbackComponent` 永不删除（spec 04 §4.4），只看「有击退组件」会让普通走路撞墙把几秒前的陈旧击退重新引爆。
  - **必须 `dot < 0`**：「被墙阻挡」= 墙把你顶回去；贴墙滑行时推出与击退垂直（`dot ≈ 0`），不该吃伤害。
  - **必须清零击退**：否则硬直期间每拍重新撞进墙 ⇒ 每拍结算一次（8 拍 = 8 次伤害）。清零是「墙吸收击退」的物理表达，且不需要额外「已撞过」标记。
  - **刷新硬直种 `0` 而非 `1`**：`MovementSystem` 在 `StateSystem` **之前** ⇒ 进入拍**会被计入**（与 `DASHING`/`ATTACKING` 同相）。`CollisionSystem` 种 `1` 是因为它在 `StateSystem` **之后**（进入拍不计入）。**两处相位相反，补偿相反，不是不一致。**
  - 撞墙伤害走 `applyDamageWithArmor`，但**实践上总落 HP**：站立护甲豁免 `HITSTUN`，而撞墙前提就是 `HITSTUN` ⇒ 能撞墙的身体护甲必然已破。撞墙**不顿帧**（打击感由硬直刷新 + 击退骤停表达）。
- **投射物 = `ProjectileComponent`（零字段标记）+ `Transform` + `Velocity` + `Hitbox`**。零字段是刻意的：位置/速度/伤害/寿命全在既有组件里，复制会造成第二真相源。**自驱判据必须是肯定式的**（「有 `ProjectileComponent`」），不能用「有速度但没意图」这种否定式判据（会在未来任何无意图实体上静默放行）。`integrateKinematic` **不加死亡/冻结门**（投射物无 `HealthComponent` ⇒ `DeathSystem` 永不打标；无 `FreezeComponent` ⇒ `isFrozen` 永假）——加不能触发的门是掩盖未来接线错误的死代码。
- **投射物 `hitstopTicks = 0` 是正确性而非手感**：`CollisionSystem` 会冻结命中**双方**，而投射物的 owner 是**远处的施法者** ⇒ 非零顿帧会让射手被自己的子弹冻住。取 0 + `knockbackForce = 6 > 0` ⇒ 反馈门仍开（受击者进 `HITSTUN` 被推开），施法者不受影响。
- **`destroyOnHit`**：`CollisionSystem` 在「伤害 + 反馈 + `HitEvent` 全部写完之后」`world.destroyEntity(hitboxId)` 并 `break` ⇒ 一投射物一目标，无需 `hitEntities` 护栏防穿透（护栏仍写入作为审计痕迹）。**`destroyOnWall`**：`MovementSystem` 解算中销毁 ⇒ 先于 `CollisionSystem`，不可能穿墙打到墙后目标。
- `spawnProjectile` / `createWall` 是各自模块的**唯一装配点**（与 `spawnCombatant` 同构）；墙**不带 `TransformComponent`**（AABB 即本体，结构上表达「墙不是会动的东西」，也不会被积分/快照碰到）。

### 变异测试（7/7 全被捕获）—— 含一次真实发现

⚠️ **M5 第一轮「未被捕获」**：G4 最初写 `hitbox.hitstopTicks === DEFAULT_CAST_HITSTOP_TICKS` —— **用构造该字段的同一个常量去校验它 = 恒真断言**，重调常量时组件与断言一起变。修法：调参用**字面量**单独钉桩（`DEFAULT_CAST_* === [20,0.4,8,60,0,6,0.5]`、`DEFAULT_WALL_SLAM_DAMAGE === 12`）+ 补一条**行为**断言（施法者未被自己的投射物冻住）。**教训：所有「组件字段 === 构造它的那个常量」都是恒真断言，必须另配字面量或行为断言。**

### 铁律级结论（后续必须遵守）
- **管道首次扩到 16 段**：`… → AISystem → **HazardSystem** → MovementSystem → …`。三面理由都不可换：① 在 `AISystem` 之后（脉冲本拍由 AI 抬升）② 在 `CollisionSystem` 之前（爆破必须生成当拍被测试 ⇒ `activeTicks = 1` 才有意义）③ **在 `MovementSystem` 之前是刻意的**（落点取「本拍移动前」坐标 ⇒ 本拍位移就是玩家的走位窗口；排在其后会把闪避降级成「被追到仍锁定」）。**M7-T01 的「不加段」结论只适用于「同一实体的位移相位」；Hazard 有独立生命周期 + 独立事件源，塞进任何既有系统尾部都会制造职责不明的杂项分支。**
- ⚠️ **钉桩实际是 7 处不是 6 处**（此前记忆漏了 `tests/physics/walls_and_projectiles.test.ts`）。改管道前用 `grep -l "'TransformSnapshotSystem'" tests/` 现场核对，不要凭记忆。
- **Hazard 的结构即契约（I1/I2/I3）**：只挂 `TransformComponent` + `HazardComponent`。**不挂 `HitboxComponent`**（预警结构上无法造成伤害）、**不挂 `HurtboxComponent`**（不能被打）、**不挂 `FactionComponent`**（否则会进 `CollisionSystem` 目标集与 AI 索敌集；阵营存在 `HazardComponent.faction` 里）、**不挂 `VelocityComponent`**（否则会被 `resolveWalls` 推走）。渲染层分类顺序必须是 **hazard → hitbox → faction**，否则预警会被当作「无视觉契约实体」静默跳过。
- **倒计时是「先判后减」**：`if (delayTicks > 0) { delayTicks -= 1; continue; } else { detonate }`。`delayTicks = N` ⇒ 恰好 N 拍预警 + 第 N+1 拍爆破（`T+N`）。**`N = 0` 是合法极限 = 同拍立即爆破**（没有「至少等一拍」的特例）。改成「先减后判」会让常数整体差一拍。
- **`HazardSystem` 相位顺序 A（播种）→ B（倒计时）不可交换**：B 必须看见 A 本拍刚播种的雷，否则「脉冲埋雷」比「直接 `spawnHazard`」晚一拍 —— 两条路径会给出不同的时序答案。
- **Hazard 不受顿帧**（I4）：`HazardSystem` 不读 `isFrozen`（对 Hazard 与对施法者都不读）。顿帧暂停的是**动作**，预警是**环境**；把两个正交时间轴耦合会让「冻住的怪顺带延长引信」。
- **爆破圆的 `ownerEntityId` 是 Hazard 自身，不是施法者**（R3，高影响）：`CollisionSystem` 的 owner 门会跳过「owner 已死」的判定圆 ⇒ 若 owner 是敌人，「前摇完成埋雷 → 玩家在 30 拍内打死敌人」会让**已埋好的雷失效**，恰恰废掉延迟 AoE 最需要成立的场景。Hazard 爆破后立即销毁，而 `isDead` 对已销毁 id 返回 `false` ⇒ owner 门结构上不可能退役它。**先建爆破圆、后销毁 Hazard。**
- **爆破 `activeTicks = 1`**（与 Zeus/Poseidon 的 `2` 相反）：`HazardSystem` 在 `CollisionSystem` **之前** ⇒ 生成当拍即被测试，`LifespanSystem` 当拍末销毁 ⇒ 恰好一次测试。`destroyOnHit = false`（AoE 必须命中半径内所有敌对目标）、`hitstopTicks = 0` + `knockbackForce = 10 > 0`（同投射物理由：别冻住远处的施法者，但保持反馈门开）。
- **`wantsToHazard` 是第四个单 Tick 脉冲**，契约与前三个逐条相同。⚠️ **消费方查询必须是「所有战斗单位」（`Intent` + `Transform` + `Faction`），不能只查有 `HazardCasterComponent` 的实体** —— 否则写在非埋雷者身上的脉冲会**永久滞留**（违反「绝不缓冲」）。全员读取并清除；只有埋雷者播种。三处清零同步：`FreezeSystem` / `DeathSystem` / `AISystem`（每拍开头清本拍决策）。
- **落点 = 施法者的 AI 目标坐标**（`AIControllerComponent.targetEntityId`，仍存活且有 `Transform` 时），否则退化为自身坐标。这是引擎里唯一「一个敌人在瞄谁」的权威；不要在 `IntentComponent` 上再造位置字段（意图层持有空间数据会破坏「意图是纯逻辑」）。
- **`GameStateComponent` 是全局单例 + opt-in**：`GameStateFactory.spawn` 是唯一装配点；**缺失 ⇒ 一律按 `PLAYING` 解释**（`findGameState` 返回 `undefined`）⇒ 所有 M1–M7 世界逐位不变（AC-11）。**绝不能在 `RunLifecycleSystem`/`DeathSystem` 里惰性创建它** —— 那会凭空多一个实体，直接打断 `death_and_encounter` G8 的 `entityCount` 断言。
- **玩家判据 = `PlayerInputComponent`**（不是 `Faction.Player`）：硬件输入组件在引擎里是结构性唯一，阵营是可被未来玩法改写的标签。
- **RUN_FAILED 只加两道门，各有独立行为断言**：① `PlayerControllerSystem.deriveIntent` 的 `suppressed`（与抽奖压制**同一个布尔**、同一个 choke point）② `EncounterSystem` 循环首行的 `return`。**门 ① 的独立性靠对抗性测试保证**：手工把 `status` 置 `RUN_FAILED` 而不杀玩家 ⇒ 只有门 ① 能让「活着的玩家零意图」成立。门 ② 的独立性靠**对照组**保证：同脚本活玩家会正常推进到 `WAVE_CLEAR` / `nextSpawnTick = 11`。
- **`RUN_FAILED` 不暂停 `step()`**：尸体 FX / 敌人回 IDLE / `LifespanSystem` 照常跑。换取「含死亡的输入脚本可重放」。`RUN_FAILED` 单调（只由 `DeathSystem` 写一次，只能被 `restartRun` 整体重建复位）。
- **`World.clearEntities()` 绝不重置 `nextId`**（I8 / **P0**）：`GameRenderer.retired` 依赖 id 永不复用；归零会让重启后的玩家拿到一个**已在 `retired` 里**的 id ⇒ 玩家在画面上**永久隐身**，且**逻辑层测试完全看不见**。已用 AC-09 机器验证（`playerIdOf(sim) > lastIdBefore`）。
- **`restartRun` 六步顺序即契约**：`clearEntities → reseed → input.clear() → scheduler.reset() → clock.reset() → runSetup(world)`。`input.clear()` 必不可少（否则新一局第一拍收到**上一局的输入**）；`scheduler.reset()` 走新增的**可选** `System.reset?()` 钩子（只有 `DeathSystem` 与 `ModifierSystem` 实现——它们持有 Tick 级总线；其余系统无跨 Tick 状态，**不需要**实现）。
- **`runSetup` 是构造期选项而非 `restartRun` 的参数**：任务要求的签名是 `restartRun(newSeed?)`，而「一局长什么样」是装配知识；放进 `GameSimulatorOptions` 让模拟器在**不认识任何游戏概念**的前提下拥有重建一局的能力。**首次装配也走同一个 `buildRun`**（`main.ts`），否则「重启 == 全新开始」不成立。
- **`newSeed ?? rng.seed + 1`**：递增而非随机 —— 确定性要求（ADR-004）。种子仍**不是**逻辑层凭空发明的：要么来自调用方，要么是已有种子的纯函数。
- **`Random.reseed` 原地改写状态、不换对象**：任何装配期捕获了 `world.rng` 引用的代码在重启后仍指向**当前**生成器。`Random.seed` 因此从 `readonly` 放宽为可变（ADR-004 §Decision 3 的原意是「无墙钟熵、无中途重播」，不是「字段永久不可变」）。
- **表现层**：Hazard 预警用 `totalDelayTicks` 算进度（`1 - delayTicks / totalDelayTicks`，clamp `[0,1]`，`total<=0` 取 1）⇒ 动画与「真正会引爆的那一拍」永远一致，渲染层**不需要自己记住初始引信长度**。死亡覆盖层与奖励草稿共用 `#ui-layer`（`.is-death` 区分），**死亡优先**；R 键监听**随覆盖层挂载/卸载**（否则会在活着的局里触发 `onRestart`）。
