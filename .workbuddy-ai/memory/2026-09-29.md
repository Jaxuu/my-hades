1. `EnemySpawnOptions` 被 `EncounterStateComponent.ts` / `EncounterSystem.ts` 从 `spawn-helpers` 导入，
   但它实际定义在 `EnemyFactory.ts` → TS2305 ×2。
   **修法**：把 `EnemySpawnOptions` 的**声明**上移到 `spawn-helpers.ts`（`type EnemySpawnOptions = CombatantSpawnOptions`），

   理由：`components` 层不该反向依赖 `prefabs` 的工厂实现；`spawn-helpers` 是装配词汇的公共之家。
   坑：**只写 `export type { X } from './y'` 不会把名字带进本地作用域**，工厂内部使用 `X` 必须同时 `import type`。

### 关键发现 1：`trackedEntityIds` 在 `ROOM_CLEARED` 时**保留**最后一波名单
我最初的规格与测试都写成「进入终态时清空」，实测是保留。想清楚后**实现是对的**：
空列表的含义是「本波尚未生成」，把它留空等于对一场**已经打完**的房间说谎。
⇒ 已修正 spec §3.2 / §4.3 / §6.2 的表述与测试断言。
（只有「提升到下一波」的 `WAVE_CLEAR` 分支才清空名单。）

### 关键发现 2：`CollisionSystem` 的 target 门 (b) 被同 Tick 门 (c) **完全覆盖**
因为死亡的定义就是 `hp <= 0`，所以「已挂标签」⇒「`hp <= 0`」⇒ 门 (c) 也拦得住。
⇒ 门 (b) 在日常场景下是**廉价提前退出**（少取 4 个组件 + 少算一次距离），不是唯一防线。
⇒ 想让它**可被独立断言**，测试必须构造一个「带标签但 `hp > 0`」的实体——
正常玩法产不出来，但这恰好钉住了真正的契约：**门的键是标签，不是血量数字**（未来加治疗/复活时不会静默失效）。

### 关键发现 3：死亡门控的**冗余是好事，但会掩盖测试空洞**
首轮变异测试（临时把 `if (isDead(...))` 改成 `if (false && isDead(...))`）发现：
- MovementSystem 的门**未被捕获**：因为尸体死时带着 `FreezeComponent`（`hitstopTicks+1`），
  而 FreezeSystem 跳过死物 ⇒ 计数永不递减 ⇒ `isFrozen` 恒真 ⇒ 冻结门顺手把尸体拦住了。
  **破法**：用 `hitstopTicks = 0, knockbackForce = 12` 的判定圆（纯击退、不结冰）杀死目标，
  尸体于是「有在飞击退但没冻结」，MovementSystem 的门成为唯一防线。
- CombatActionSystem / DashSystem / StateSystem / StatusEffectSystem 的门同理不可观测
  ⇒ 用**对抗性探针**（手工给尸体写 `wantsToAttack` / `wantsToDash` / 手工挂 poison）独立钉住。

**最终 13 处变异全部被捕获**（3 道 Collision 门 + 9 个系统的死亡门 + DeathSystem 的重复事件守卫与意图中和）。
脚本要点：变异 → 跑单文件测试 → 还原；`grep` vitest 摘要行必须加 `NO_COLOR=1`，
否则 ANSI 转义码会让 `^ *Tests +[0-9]` 匹配失败（这个坑让我白跑了一轮）。
