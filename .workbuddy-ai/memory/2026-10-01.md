## 关键架构决策（后续改这里前必读）

1. **事件桥接 = `TeeEventQueue<T> extends EventQueue<T>` 覆写 `emit`**（先留客户端副本、再 `super.emit`），三个 tee 队列注入 `createDefaultSystems(hit, death, dash)`。**这是本里程碑最重要的发现**：`EventQueue` 的 `emit/drain/clear` 全是 public，所以「留存瞬时事件」根本不需要动 `src/` —— 比任务书设想的 `GameSimulator.onFrameEnd(events)` 更干净（后者要把一个**纯表现层概念**注入 `src/core`）。类型上完全 Liskov 兼容，管道仍只看到普通 `EventQueue`。
2. **客户端缓冲不受 `scheduler.reset()` 管辖**：`restartRun` 只会让 `DeathSystem`/`ModifierSystem` 清**它们自己的**总线，客户端缓冲不在调度器里 ⇒ 必须在 run 边界显式 `bridge.clear()`（`main.ts` 的 `onStartRun` 与 `onReload` 两处），否则会把引用「刚被销毁的实体」的事件重放到新一局。
3. **`drainFrame()` 每渲染帧恰好消费一次**：落在 `GameLoop.syncFrame(alpha)`，是 `renderer.syncWorld` 的**唯一**调用点（HUB 早退分支与正常分支都走它），所以既不会漏 drain 也不会重复 drain。一帧内最多 5 个逻辑 Tick 的事件会在缓冲里累积。
4. **粒子层走「惰性挂载」而非常驻节点**：`particleLayer` 只在「至少一个粒子存活」时挂进 `cameraContainer`（插在 `root` **之前**），清空即摘除。理由见下条——任何**常驻**新场景节点都会撞坏六条冻结契约之一。空闲态场景图与 M14 前**逐位相同** ⇒ 五个既有渲染套件**一行未改**。
5. **⚠️ 六条渲染场景图冻结契约**（M5/M12 遗留，改渲染前必查；测试里的 `renderRoot()` 助手写法是 `camera = stage.children[0]`、`root = camera.children[length-1]`）：
   - F1 `app.stage.children` 长度 1 且 `[0] === camera`
   - F2 `camera.children[last] === root`
   - F3 `root.children[last] === fxLayer`
   - F4 `root.children[0]` === 首个实体视图
   - F5 无墙时 `camera.children` 长度**恰为 1**（有墙时 2：`[0]`=静态层）
   - F6 空闲时 `fxLayer.children` 长度**恰为 0**
   **推论**：往 `stage`/`camera`/`root`/`fxLayer` 加**常驻**子节点，必然撞坏 F1–F6 中的一条。合法路线只有两条：(a) 惰性挂载（本次采用，先例是 `staticLayer`）；(b) 常驻 + **显式同步钉桩测试**（先例 M12-T02 / spec 20 §6.3）。**禁止**为让测试通过而放宽语义或删断言，长度断言只能改成新的精确字面量。
6. **`howler` 的导入图隔离 + 真因（勿再误传）**：`howler` 只被 `client/AudioManager.ts` 导入，`AudioManager` 只被 `main.ts` 导入，**`GameRenderer` 的导入图不含 howler**（node 渲染套件只导入 `GameRenderer`）。⚠️ 隔离的**真因不是**「howler 在 import 期会炸」—— 该前提已被**实测推翻**（node 下 howler 导入正常、`new Howl` 亦不抛）。真因是 `AudioManager` 曾引用**裸 DOM 全局 `window`**，被 `tests/**` 传递导入后会让**无 DOM 的 `npm run typecheck`**（`lib: ["ES2022"]`）报 **TS2304**；现以 `typeof (globalThis as { window?: unknown }).window` 守卫规避。
7. **`GameLoop` 只经不含 howler 的 `AudioSink` 结构化接口碰音频**（`playHit/playDash/playCoin`），构造参数**加性可选**（`bridge`、`audio` 默认 `null`）⇒ 既有 `new GameLoop(sim, renderer, input)` 行为逐位不变。
8. **占位音 = 代码合成 WAV `data:` URI + `new Howl`**（不是裸 `OscillatorNode`）：零资源文件 ⇒ **零 404**，同时让 howler 成为**真实**依赖（拥有加载/静音/音量/播放）。构造整体 `try/catch`，无 `window`/无 `Howl`/`AudioContext` 缺失/自动播放被拦 ⇒ `isAvailable === false` 且每个方法 **no-op，绝不抛**（I9）。
9. **金币音无事件总线**：逻辑层不发布「拾取」事件，唯一诚实信号是钱包本身 ⇒ `main.ts` 每帧读 `readGold` 的**上升沿**触发（纯观察，与 HUD 读同一份数据）。
10. **震动必须能衰减到 0**：`shakeIntensity` 随 `shakeTime` 衰减归零，否则会永久抖动并破坏 `camera_follow` 的相机收敛断言（`toBeCloseTo(..., 6)`）。无命中时 shake 恒为 0。
11. **火花原点取 `HitEvent.position`**（判定圆中心），不读目标 `TransformComponent` —— 保持 `VFXManager` 与 `World` 解耦。代价：火花不保证盖在目标身上（spec 22 §7 T3 登记）。

## 质量手法（值得复用）

- **⚠️ 本次最有价值的产出：一个被变异实验揪出的真实测试空洞**。实现者原本的 12 例里，变异实验 M1（**关掉 `syncCamera` 的震动叠加**）**没有任何断言失败** —— 说明那些用例只验证了「震动被**武装**」（`shakeTimeRemainingMs === 180`），**从未验证「震动真的施加了位移」**。`quality-lead` 补上位移钉桩（`Math.random = 0` ⇒ `camera.x/y toBeCloseTo(-6, 9)`）后该变异才被捕获。**教训：凡是「状态被设置」与「效果被施加」是两件事的机制，必须各有一条断言；只断言状态字段等于构造它的那个常量，是恒真断言陷阱的变体。**
- **端到端桥接断言不能自证**：`TeeEventQueue` 单体的「emit 转发」用例等于自证。真正的证据是**真实 `GameSimulator` 打出一次命中** ⇒ `drainFrame().hits` 字段**字面量**钉桩（`attackerId 0` / `targetId 1` / `hitboxEntityId 2` / `position.x 0.75` / `damage 10` / `sourceModifier null`），外加一条**转发证明**（命中触发 `zeus_strike` 修饰符 ⇒ `[null, 'zeus_strike']`，证明 tee 在喂**活**管道而不只是记录）。
- **惰性挂载必须攻击「挂载顺序交叉」**：G-B 专门构造「先粒子后墙」与「先墙后粒子」两序，断言恒为 `[static?, particle?, root]`（静态层永最底、`root` 永最后）。这是惰性层最容易出错的交叉点。
- **泄漏要用轮次压力测**：G-C 做 6 轮 spawn→expire，断言复用**同一**容器、不累积、不残留。
- **主理人复核的独立价值**：`engineering-lead` 自报「未改任何既有断言」，但**只有** `git diff --stat tests/` 为空才能真正证明（`juice_m14.test.ts` 是未跟踪新文件，改它不入 diff —— 这一点必须自己想清楚，否则会误判）。
