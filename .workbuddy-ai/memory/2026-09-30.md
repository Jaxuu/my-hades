**关键设计决定（后续里程碑必须遵守）**
1. **世界坐标契约**：格 `(col,row)` 占 `[col,col+1]×[row,row+1]`，中心 `(col+0.5,row+0.5)`，房间左上角格 = 世界原点。`1×1` 格 + 半径 `0.5` ⇒ 出生在格中心**恰好与四邻边界相切**（贴边不算碰 ⇒ 不会被自己推挤）。这条相切不是巧合，是网格边长与判定半径共同选定的。
2. **`roomId` 是可选字段**：`absent ≠ empty`。出厂 `encounters.json` 每间都写，但 schema 不强求 ⇒ 所有 M1–M11 夹具（`encounters_hmr` 的 `ENCOUNTERS`、手写房间）继续合法。跨表校验只在 `loadAll`（`assertEncounterRoomsExist`）。
3. **`roomIds` 用 `(string|undefined)[]` 与 `roomWaves` 同下标对齐**，不塞进 `roomWaves`（其形状被 `economy_and_victory` 以**引用同一性**钉死），也不用哨兵空串。
4. **`GameSimulator` 保持游戏无关**：不给它加 `initialRoomId`。房间拓扑装配收敛到构造期 `runSetup` ⇒ `restartRun` 第 6 步必然重载房间 0。这是「更新 restartRun」的实现方式（注释 + G2 断言），而不是在 `src/core` 里引入「房间」概念。
5. **出生点选取 = 「随机起点 + 确定性轮转」，每波恰好 1 次抽签**（`world.rng.nextInt(0,pool-1)` 后 `pool[(start+i)%n]`）。三收益：不重叠（池 ≥ 队伍时）、流扰动是常数而非队伍规模的函数（奖励三选一同流）、`depth` 复制体自动回绕。空池 ⇒ **早退且不抽签**（零回归的关键）。

### R4 爆炸半径实测（一次性探针，已完全还原）
在 `MovementSystem.update` 的 `integrateKinematic` 与 `resolveWalls` 之间插入朴素**对半分离**（`query(Transform, Hurtbox)` 跳过 `isDead`，`i<j` 双循环，重叠则各推 `overlap*0.5`，完全重合时法线取 `(1,0)` 兜底），跑全量后按备份还原。

**两类失败原因，都是「夹具依赖实体可以重叠」**：
1. AI 敌人走进玩家身体 ⇒ 分离把它推出近战距离 ⇒ 后续那一刀**打空**（`status_effects` G2 的「第二刀叠层」断言 80 变 90，即只叠了 1 层）。

2. **`RoomLoadResult` 拆成两个计数**：`wallCount`（世界状态，= `resolveWalls` 迭代次数）+ `wallTileCount`（几何真相）。两数一起才让「合并等价」（面积和 == 瓦片数）与「没有过度合并」（每个 `1` 都被覆盖）**可分别断言**。⚠️ 这是 M12-T01 契约的**语义变更**，必须同步所有 `wallCount` 断言（本仓 4 处）。
3. **软碰撞落在 `MovementSystem` 第 3 相位，不新增管道段**：沿用 M7-T01 既定落法（"同实体位移/物理相位挂 `MovementSystem` 尾部；只有「独立生命周期+独立事件源」才新增段"）。新增段要同步 **9 处钉桩**，零行为收益。
4. **相位序 `separateBodies → resolveWalls` 即契约**：分离只懂两点距离、不懂墙；排在墙解算**之后**会把身体挤进墙里且本拍无人救回。分离先跑 ⇒ 墙拥有最终发言权，最坏是"分离推开、墙推回"。
5. **"同阵营"是刻意的窄化，也是低爆炸半径的关键**：M12-T01 的 R4 探针实测过"全体分离"只炸 4 个用例，但那 4 个全是**玩家 vs 敌人**（AI 走进玩家身体 ⇒ 近战打空；冲刺穿过敌人 ⇒ 静止位置改变）。限定同阵营后爆炸半径为 **0**，且正对 R4 要解决的"同阵营敌人完美重合"。
6. **完全重合的防死锁 = `EntityId` 派生方向**（`Math.imul` 混合 + 16 槽 + `>>>0`），**零熵**。注意该函数**不必对称**（`angle(a,b) ≠ angle(b,a)` 无害：两体只需被推向相反方向）。
7. **位移不乘 `fixedDeltaSeconds`**：这是**位置修正**不是速度积分；乘 dt 会让完全重合的一对每拍只修一部分 ⇒ 抖动若干拍。不乘 ⇒ 单趟到相切且**稳定**（下一拍 `distSq >= minDist²` 直接跳过）。
8. **分离不设冻结/硬直门**（与 `resolveWalls` 同论据：几何不变量 ≠ 动作）。QA 用三类探针确认冻结体/硬直体**仍会被同阵营伙伴推开**，多拍收敛。**登记一处不对称**：墙解算下冻结体不可能"新穿透"，分离**能**推动冻结体 ⇒ 已进 spec 20 §7。
9. **场景图三层 `stage → camera → {staticLayer, root}`**：`root` 的内部子序**一字未动**（`root.children[0]`=首个实体视图、`last`=`fxLayer` 两条 M5 冻结契约仍成立），相机只是**包裹**旧 root 而不重排它的孩子。代价：`stage.children[0]===root` 这条 M5 契约被改写 ⇒ 4 处测试同步（3 个 `renderRoot` 助手 + 拓扑 G5）。
10. **`syncCamera` 读插值后的视图坐标**（不是 `TransformComponent`）：相机跟的是玩家**看得见**的位置，否则相机与玩家视图差半帧。
11. **假 `Application` 无 `screen` ⇒ 降级 0**，且**绝不读 `app.renderer.*`**。QA 用"抛异常的 `renderer` getter"证明渲染层只读 `app.screen`。真实屏幕尺寸路径（`screen={800,600}` ⇒ 目标 `(385,285)`）**原套件零覆盖**，是 QA 补上的真实空洞。

## 关键架构决策（后续改这里前必读）

1. **`SaveState` 不是组件、不进 `snapshot()`、`restartRun` 不重建**。它是 `GameSimulator` 的**注入**字段（`initialSaveState`），`sim.saveState` 返回**注入实例本身**（调用方自己持有的句柄能看到每次变化）。若挂成组件，就会被它必须存活的那个操作（`clearEntities`）销毁。
2. **暗影是「两本账」**：局内写 `InventoryComponent.darkness`（Run 内、快照可见、随 Run 销毁），**唯一**跨界写点是 `GameSimulator.enterHub()` → `bankRunDarkness`（入账 + **清零 Run 账本**）。清零是幂等护栏：没有它，营地进出两次就发两次钱。
3. **`HUB` 必须是 `isRunOver` 的一员**（这是本任务最容易被漏掉的一行）。若漏，进入营地会**重新打开** `RUN_FAILED` 关掉的每道门（调度器在尸体上刷怪、拾取继续结算）。`PLAYING` 是唯一「未结束」状态。
4. **营地是「状态」不是「系统」** —— 所以 9 处管道钉桩 + 5 处段数钉桩**零改动**。这是选择「status + 覆盖层」而非「新系统 + 新事件」的主要理由。
5. **局外加成在 `runSetup` 期解析成纯数字**（`resolveMetaBonuses` → `MetaBonuses`），`spawnCombatant` 只做算术。`spawnCombatant` 被 `step()` 间接调用（`EncounterSystem` → `EnemyFactory.spawn`），内部**不能**有会抛的 id 查表。
6. **`runSetup` 的签名扩成 `(world, saveState)`** —— 加性，既有单参数 lambda 零改动。这是「装配器可能想看存档」进入 `src/core` 公开契约的唯一代价。
7. **`GameSimulator` 因此多了两个游戏概念**（`enterHub` / `purchaseMetaUpgrade`），与它「不知道什么是玩家/房间/游戏状态」的原注释相冲突 —— 已在 spec 21 §8 诚实登记。理由：运行边界操作必须能被调用方**对着模拟器**发出（同 `restartRun`）。
8. **存档 schema 严格抛、`SaveStore` 尽力而为**：`SaveState.from` 对坏值抛 `TypeError`/`RangeError`（数据来自进程之外），但 `client/SaveStore` 把任何失败降级成「从头开始」。这与数据层的「畸形 JSON 必须中止启动」**刻意相反**（构建产物 vs 玩家数据）。
9. **未知天赋 id 跳过、不抛**：存档比构建活得久，配置改名是正常事件。`resolveMetaBonuses` 先 `hasMetaUpgrade` 再 `getMetaUpgradeConfig`。
10. **`thick_skin` 发货价 = 30**，不是任务书 §Task 2 示例里的 100 —— 因为 §Task 4 的可执行断言是「花 30 剩 20」（`50 − 30 = 20`）。**互相矛盾时以可执行断言为准**（spec 21 I11）。
